# Addition

**Can a transformer trained to do long addition in a few bases, each defined in the prompt, add in bases it never saw in training?**

See [`spec/task.md`](spec/task.md) for the task specification, [`reference.py`](reference.py) for the ground-truth column-addition oracle, [`inputs.py`](inputs.py) for shared tokens, sequence prefixes, and problem sampling, [`evaluation.py`](evaluation.py) for shared evaluation metrics and the first-error taxonomy, [`config.py`](config.py) for experiment configuration and evaluation-split schemas, [`train_and_evaluate.py`](train_and_evaluate.py) and [`run.py`](run.py) for the training/evaluation runner and CLI entry point, [`variants/cls/`](variants/cls/) for the per-step parallel classification variant ([`spec/variants/cls.md`](spec/variants/cls.md)), [`variants/step_fork/`](variants/step_fork/) for the per-step branching query variant ([`spec/variants/step_fork.md`](spec/variants/step_fork.md)), [`variants/step_ar/`](variants/step_ar/) for the per-step autoregressive variant ([`spec/variants/step_ar.md`](spec/variants/step_ar.md)), [`variants/ar/`](variants/ar/) for the full-trace autoregressive variant ([`spec/variants/ar.md`](spec/variants/ar.md)), and [`variants/addressed_step_ar/`](variants/addressed_step_ar/) for the explicitly base-`B` addressed per-step autoregressive variant ([`spec/variants/addressed_step_ar.md`](spec/variants/addressed_step_ar.md)).
