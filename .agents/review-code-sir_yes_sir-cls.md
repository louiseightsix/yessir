## 1. Historical Provenance Summary (`results/sir_yes_sir/` & `studies/sir_yes_sir/`)

1. **No current `cls` runs exist yet in `results/sir_yes_sir/`**: Across all 14 run directories under `results/sir_yes_sir/`, 8 record `"variant": "ar"` and 6 record `"variant": "sm_mh"` (the draft state-machine predecessor renamed and redesigned into `cls` across commits `89350f7` and `2db3181`).
2. **Every historical run is properly quarantined as `OUTDATED`**: All 14 run directories carry `OUTDATED: built against draft spec` on line 1 of their `README.md` (matching [results.md](file:///atelier/code/workshop/yessir/.agents/results.md#L13-L19)), and all 8 study files under `studies/sir_yes_sir/*.json` currently have `"status": "draft"`, `"runs": []`, and `"conclusion": null`. No live claim rests on historical runs.
3. **Why the historical `sm_mh` runs (`a13cc88`, `586f44d`, `86e46ea`) are incompatible with `HEAD` `cls`** (verified via `git show <sha>:...`):
   - **3-head target vs 2-head target**: At `a13cc88` and `586f44d`, `reference_step` returned a 3-tuple `(o_k, w_k, flag_k)` including a wrap-around indicator `w_k` (`s_1` if `i == B - 1` else `s_0`), supervised by a 3-head `MultiTaskHead` (`num_classes=(256, 256, 256)`, initial loss `3 * ln(256) = 16.64`, matching the step-1 losses `16.20`–`17.03` in `train.jsonl`), whereas `HEAD` `cls` uses 2 heads `(o_k, flag_k)` (`initial loss ≈ 2 * ln(256) = 11.09`).
   - **Sequence layout & position coupling**: `sm_mh` appended an explicit `[STEP]` query token (`(*out_tokens, SpecialToken.STEP)`) with `TokenType.OUTPUT` starting at `position_id = 0` (placing `o_0` at `0` and `[STEP]` at `k`), whereas `HEAD` `cls` shares the exact `[BOS] alphabet [SEP] x [SEP] output` sequence of `ar`, querying at the second `[SEP]` (`position_id = 0`) for `k = 0` and at `o_{k-1}` (`position_id = k`) for `k >= 1`.
   - **Supervision & batching**: `sm_mh` only emitted `L` single-step examples per problem (no `single_pass` mode) and always resampled alphabets (`resample_alphabet` did not exist, so `symbol_set: "decimal"` in `champion-fox`, `direct-ghost`, and `innocent-monkey` actually shuffled `4` digits drawn from `'0'..'9'`). `fixed_d_model` also did not exist (`champion-fox` and `direct-ghost` ran with shrinking `d_model`).
   - **Inflated historical `halt_accuracy` and stricter `step_accuracy`**: At `a13cc88` and `586f44d`, `evaluate_sm_mh` computed `halt_accuracy` **per step** (`sum(halt_ok_list) / total_steps`) rather than **per problem**, and required all 3 heads `(o_k, w_k, flag_k)` to match for `step_accuracy`. Per-step halting suffers from `1 - 1 / L` class-imbalance inflation—visible in [eval.json](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-direct-ghost/eval.json#L1-L5) (`exact_match = 0.0`, `halt_accuracy = 0.9966666666666667 = 299/300`)—which `HEAD` fixes by scoring `halt_accuracy` per problem. Four of the six `sm_mh` runs also had `"git_dirty": true`.

### Finding 1 (Medium — Study-vs-Code Mismatch): Three draft studies ask questions that `sir_yes_sir` cannot currently measure or evaluate post-hoc

- **Files**:

  - Code: [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L71-L80), [run.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/run.py#L26-L43), [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/evaluation.py#L22-L24), [evaluation.py (cls)](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/evaluation.py#L112-L135), [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/train_and_evaluate.py#L102-L130)
- **Expectation vs actual code behaviour**:
  1. **Length generalisation (`sequence-length.json`, `embedding-modes.json`)**: Both studies ask how models trained at a fixed `L` generalise to unseen input lengths. In [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L74), `x_length: int = 3` is a single fixed integer; [run.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/run.py#L26-L43) passes the exact same `x_length=config.x_length` to both `train_dataset` and `eval_dataset`; and [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/train_and_evaluate.py#L113-L129) logs only `"splits": {"id": ...}` without saving model weights. Furthermore, when trained at a single fixed `L` (e.g. `L = 3`), every training problem has `flag_k == FLAG_FINISHED` at `k == L - 1` (`position_id == 2`), giving the halting head a constant positional shortcut and zero exposure to `position_id >= L`.
  2. **Wrap-around accuracy (`alphabet-length.json`)**: Asks how *"wrap-around accuracy (`x_k == s_{B-1} -> s_0`)"* scales with `B` from `2` to `240`. Neither [EvalMetrics](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/evaluation.py#L22-L24) nor [evaluate_cls](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/evaluation.py#L112-L135) inspects `x_k` or stratifies accuracy by `x_k == alphabet[-1]` vs `x_k != alphabet[-1]`, and no checkpoint is saved to evaluate wrap-around accuracy after a run finishes.
  3. **Direct test of transition memorisation (`memorisation-vs-in-context.json`)**: Asks whether training on a fixed canonical alphabet (`resample_alphabet=False`) causes the model to memorise static token-to-token transitions rather than attending to the prompt's alphabet section. Because [run.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/run.py#L35-L43) also sets `resample_alphabet=config.resample_alphabet` (`False`) on `eval_dataset`, a model that completely ignores the prompt's alphabet section still scores `exact_match = 1.0` on `eval.json`; distinguishing weight memorisation from in-context lookup directly requires an OOD shuffled-alphabet eval split (otherwise it can only be inferred indirectly, e.g. from `n_layers=1` succeeding on canonical order and failing on `resample_alphabet=True`).
- **Concrete trigger**: Running `./yessir.sh run sir_yes_sir cls --x-length 3` or `--alphabet-size 64` produces `eval.json` containing only in-distribution `{"exact_match", "step_accuracy", "halt_accuracy"}` at `L = 3` and no saved weights.
- **Plausible impact on headline numbers**: Does not corrupt current numbers (`runs: []`), but prevents executing those three studies as stated without extending `EvalMetrics` / eval splits.

### Finding 2 (Medium — Experimental Confound): `ClsSupervision.ALL_STEPS` consumes `1 / L` as many problems per step and packs correlated steps of the same problem into each minibatch

- **Files**: [dataset.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/dataset.py#L67-L88), [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L302-L308), [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/train_and_evaluate.py#L79-L117), [cls-training-passes.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/cls-training-passes.json#L5)
- **Expectation vs actual code behaviour**:
  - [cls-training-passes.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/cls-training-passes.json#L5) compares *"sample efficiency, wall-clock cost, and final accuracy"* across `single_pass`, `all_steps`, and `random_step`.
  - In [dataset.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/dataset.py#L67-L88), each problem `(alphabet, x)` from `iter_problems` yields `1` `LabelledExample` in `single_pass` (`L` supervised positions), `1` `LabelledExample` in `random_step` (`1` supervised position), and `L` consecutive `LabelledExample`s (`k = 0 .. L - 1`) in `all_steps` (`1` supervised position each).
  - [train](file:///atelier/code/workshop/yessir/yessir/training.py#L303) always draws `batch_size` `LabelledExample`s per optimiser step (`itertools.islice(stream, batch_size)`), with no shuffle buffer, and [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/train_and_evaluate.py#L79-L117) logs only optimiser `step` (not `problems_seen` or `supervised_steps_seen`).
  - Consequently, at fixed `(batch_size = B_batch, max_steps = S)` for sequence length `L`:
    - `single_pass` sees `S * B_batch` distinct problems and `S * B_batch * L` supervised step targets (`B_batch` independent problems per gradient step).
    - `random_step` sees `S * B_batch` distinct problems and `S * B_batch` supervised step targets (`B_batch` independent problems per gradient step).
    - `all_steps` sees only **`S * B_batch / L` distinct problems** and `S * B_batch` supervised step targets, with all `L` steps of each problem packed **contiguously inside the same minibatch** (and when `B_batch` is not a multiple of `L`, boundary problems split across adjacent optimiser steps; when `L >= B_batch`, an entire minibatch contains only `1`–`2` distinct `(alphabet, x)` problems).
- **Concrete trigger**: Under the default hyperparameters `SirYesSirClsConfig(supervision="all_steps", batch_size=64, x_length=3, max_steps=1000)`, `single_pass` and `random_step` train on `64,000` distinct problems over `1,000` steps, whereas `all_steps` trains on only `21,334` distinct problems (`21.33` problems per batch, splitting problem `21` across steps `1` and `2`). At `x_length = 64, batch_size = 64`, every `all_steps` minibatch of `64` items consists of `k = 0 .. 63` of a **single** problem `(alphabet, x)`.
- **Plausible impact on headline numbers**: **Yes, for `cls-training-passes.json`.** Comparing `all_steps` vs `single_pass` or `random_step` at equal `max_steps` and `batch_size` conflates supervision mode with a `1 / L` reduction in distinct problems seen and `L`-fold intra-batch problem correlation (effective problem batch size `B_batch / L`). Runs in `cls-training-passes.json` must explicitly decide whether to match optimiser steps, problems seen (`max_steps` scaled by `L`), or problems per batch (`batch_size` scaled by `L`).

### Finding 3 (Low-to-Medium — Diagnostic Metric & Head-Parameter Asymmetry): `256`-class halting head and teacher-forced `evaluate_cls` create subtle `halt_accuracy` / `step_accuracy` differences vs `greedy_generate_cls` and `ar` when `exact_match < 1.0`

- **Files**: [run.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/run.py#L48-L50), [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/evaluation.py#L112-L130), [generation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/generation.py#L66-L73), [evaluation.py (ar)](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/evaluation.py#L107-L120), [cls-vs-ar.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/cls-vs-ar.json#L5)
- **Expectation vs actual code behaviour**:
  - **Headline `exact_match` is unaffected**: As verified analytically and empirically below, teacher-forced `exact_match` in `evaluate_cls` equals free-running `greedy_generate_cls` `exact_match` (and is strictly comparable to `evaluate_ar` `exact_match`).
  - However, three diagnostic/architectural asymmetries matter when comparing `cls` and `ar` (e.g. in `cls-vs-ar.json` and `minimum-model-size.json`):
    1. **`256`-way `heads[1]` vs binary halting (`halt_accuracy` vs `greedy_generate_cls`)**: [run.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/run.py#L49) sets `num_classes=(VOCAB_SIZE, VOCAB_SIZE)` (`(256, 256)`) so raw `SpecialToken` IDs (`FLAG_CONTINUE = 245`, `FLAG_FINISHED = 246`) serve directly as class indices, leaving `254` dead classes on `heads[1]`. In [generation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/generation.py#L70-L71), generation halts only on `flag_k == SpecialToken.FLAG_FINISHED` (`246`) and continues on all `255` other byte values—matching [evaluate_ar](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/evaluation.py#L114-L115) (`preds[k] != SpecialToken.EOS`) and the prose in [task.md](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/spec/task.md#L80). By contrast, [evaluate_cls](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/evaluation.py#L125) (matching [cls.md](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/spec/variants/cls.md#L59)) checks `pred_flag == target_flag`, requiring `pred_flag[k] == 245` at `k < L - 1`. If an early-training model predicts `pred_flag = [0, 0, 246]`, `greedy_generate_cls` executes all `3` steps and halts at the exact right step, whereas `evaluate_cls` reports `halt_accuracy = 0.0`.
    2. **Premature-halt decoupling in `step_accuracy` (`cls` vs `ar` and vs free-running rollout)**: Because `cls` predicts `o_k` (`heads[0]`) and `flag_k` (`heads[1]`) in parallel under teacher forcing, a model that predicts `FLAG_FINISHED` at `k = 0` (halting `greedy_generate_cls` after `1` step) while predicting `pred_o = [o_0, o_1, o_2]` scores **`step_accuracy = 1.0`** in `evaluate_cls` (`exact_match = 0.0`, `halt_accuracy = 0.0`). In `ar`, emitting `EOS` at `k = 0` occupies the single token prediction slot (`preds[0] = EOS != o_0`), capping `evaluate_ar` `step_accuracy` at `(L - 1) / L`. Similarly, in `NOPE` and `TOKEN_TYPE_NOPE` (where step alignment relies on causal attention over prefix tokens rather than explicit `position_ids`), teacher-forced `step_accuracy` conditions step `k` on clean ground-truth `o_{0..k-1}` rather than the model's own erroneous predictions.
    3. **Extra `262,656` output-head parameters in `cls`**: At default `d_model = 512`, `ParallelClassificationHead(512, (256, 256))` adds `262,656` trainable parameters (`512` in `head.norm` + `131,072` in `heads[0]` + `131,072` in `heads[1]`, `130,048` of which are dead rows for the `254` unused flag classes, giving initial loss `2 * ln(256) = 11.09` vs `ln(256) + ln(2) = 6.24` for a 2-class flag head), whereas `ar`'s `SubspaceLMHead` has `0` trainable parameters (`19,241,472` total parameters in `cls` vs `18,978,816` in `ar` at default settings; in small-model sweeps like `minimum-model-size.json`, the untied `cls` head can dominate total parameter count).
- **Concrete trigger** (verified via Python probe): On `alphabet = b"0123"`, `x = b"130"`, scripting `[(ord("2"), 0), (ord("0"), 0), (ord("1"), 246)]` yields `len(greedy_generate_cls(...)) == 3` halting on `246` at `k = 2`, while `evaluate_cls` returns `EvalMetrics(exact_match=0.0, step_accuracy=1.0, halt_accuracy=0.0)`. Scripting `[(ord("2"), 246), (ord("0"), 245), (ord("1"), 246)]` halts `greedy_generate_cls` at length `1`, while `evaluate_cls` still returns `step_accuracy = 1.0`.
- **Plausible impact on headline numbers**: **Zero impact on `exact_match`.** Affects only unconverged diagnostic `step_accuracy` / `halt_accuracy` curves and parameter-count accounting between `cls` and `ar`.

### Finding 4 (Low — Config & Finite-Universe Traps): `d_position` interaction in `NOPE` / `TOKEN_TYPE_NOPE`, `symbol_pool_size` no-op under `resample_alphabet=False`, and train/eval overlap on small pools

- **Files**: [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L66-L68), [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L187-L232), [inputs.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/inputs.py#L165-L175)
- **Expectation vs actual code behaviour**:
  1. **`d_position` under `TOKEN_TYPE_NOPE` and `NOPE`**:
     - When `fixed_d_model=False` and `embedding_mode` is `TOKEN_TYPE_NOPE` or `NOPE`, [effective_d_position](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L200-L204) is `0` and [effective_d_scratch](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L215-L216) returns `self.d_scratch`, making `d_position` (any even `int >= 0`) a **complete silent no-op** on both data and model architecture.
     - Conversely, when `fixed_d_model=True` (the default) and `embedding_mode` is `NOPE` or `TOKEN_TYPE_NOPE`, passing `--d-position 0` on the CLI (as was done in historical runs `champion-fox` and `direct-ghost`) sets `dropped_position = self.d_position = 0` in [effective_d_scratch](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L218-L221), **shrinking `d_model` to `480` (in `NOPE`) or `496` (in `TOKEN_TYPE_NOPE`) instead of `512`** even though `fixed_d_model=True`. Holding `d_model = 512` across modes requires keeping `d_position = 32`.
  2. **`symbol_pool_size` under `resample_alphabet=False`**: In [iter_problems](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/inputs.py#L166-L172), `fixed_alphabet = create_alphabet(symbol_pool[:alphabet_size])` slices the first `alphabet_size` symbols of `symbol_pool`. Whenever `resample_alphabet=False`, varying `symbol_pool_size` across `alphabet_size .. len(symbol_set)` is a **silent no-op** on both training and evaluation examples (even though `derived_summary()` reports the changed `symbol_pool_size`).
  3. **Independent seeds vs finite-universe overlap**: [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L66-L67) enforces `eval_seed != seed` so evaluation does not replay the training stream. In the default regime (`symbol_set="all"`, `B = 4`, `L = 3`, `resample_alphabet=True`), the universe has `(240! / 236!) * 4^3 = 207,055,380,480` problems (`~3.1e-5` overlap with `64,000` training problems). However, under canonical fixed order (`resample_alphabet=False`, `B = 4`, `L = 3`), the entire universe has only **`B^L = 64` distinct problems** (fewer than `num_eval_problems = 100`, guaranteeing duplicates inside the eval set and ~100% overlap with training after a few steps); under canonical permuted (`symbol_pool_size = 4`, `B = 4`, `L = 3`, `resample_alphabet=True`), the universe has `4! * 4^3 = 1,536` problems (`~41.7` full passes in `1,000` steps at `batch_size = 64`). Evaluation in small-`B` / restricted-pool regimes is therefore strictly **in-distribution (`id`)**, not held-out generalisation.
- **Plausible impact on headline numbers**: Passing `--d-position 0` under `NOPE`/`TOKEN_TYPE_NOPE` would quietly reduce width in an embedding ablation (`embedding-modes.json`); small-universe overlap is expected for `"id"` smoke tests (`test_convergence.py` uses `3! * 3^2 = 54` total problems) as long as results are not interpreted as unseen-problem generalisation.

### Finding 5 (Low — Minor Doc Drift & Defensive Validation Gaps)

1. **`bfloat16` autocast reference in `spec/task.md`**: [task.md](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/spec/task.md#L78) notes that teacher-forced and free-running `exact_match` may differ slightly *"under `bfloat16` autocast"*, whereas `sir_yes_sir` and [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L205) run exclusively in `fp32` with no `torch.autocast` context anywhere in `experiments/sir_yes_sir/` or `yessir/` (only `fp32` GEMM tile reduction order can differ between batch shapes).
2. **Partial `IGNORE_INDEX` check in `_validate_cls_item`**: [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/evaluation.py#L25-L29) and line 113 filter non-ignored positions solely via `step[0] != IGNORE_INDEX` (`labels[b, :, 0] != IGNORE_INDEX`), without checking `(step[0] == IGNORE_INDEX) == (step[1] == IGNORE_INDEX)` or suffix contiguity. Unreachable from `build_cls_labelled_example`, which masks both heads identically at `0 .. P - 2`.
3. **Unchecked `lengths` value range in `ParallelClassificationHead.forward`**: [heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L102-L111) checks `lengths.shape == (batch_size,)` but not `(1 <= lengths) & (lengths <= hidden_states.size(1))`; passing `lengths = torch.tensor([0])` directly to `ParallelClassificationHead` silently indexes `lengths - 1 = -1` (the final padded token). Unreachable via `collate`, because `Example` enforces `len(input_ids) >= 1`.
4. **Non-finite `lr` in `SirYesSirConfig` / `build_optimizer`**: [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L163) and [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L87) check `lr <= 0` without `math.isfinite(lr)`, so `SirYesSirClsConfig(lr=float("nan"))` passes validation (`nan <= 0` is `False`).

### 3.2 Tokenisation, sequence layout, causal masking, and train/eval parity

- **Exact sequence layout & position coupling**: Read [inputs.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/inputs.py#L65-L132) and [vocab.py](file:///atelier/code/workshop/yessir/yessir/vocab.py#L38-L48), [special_tokens.py](file:///atelier/code/workshop/yessir/yessir/special_tokens.py#L7-L20), [example.py](file:///atelier/code/workshop/yessir/yessir/example.py#L24-L90).
  - Vocabulary cleanly partitions `0x00..0xEF` (`240` symbols) from `0xF0..0xFF` (`16` special tokens: `SEP=0xF0`, `PAD=0xF1`, `BOS=0xF2`, `EOS=0xF3`, `FLAG_CONTINUE=0xF5`, `FLAG_FINISHED=0xF6`).
  - `build_example(alphabet, x, output)` builds `[BOS] s_0..s_{B-1} [SEP] x_0..x_{L-1} [SEP] o_0..o_{k-1}` with `token_type_ids` `(0, 1..1, 0, 2..2, 0, 3..3)` and `position_ids` `(0, 0..B-1, 0, 0..L-1, 0, 1..k)`.
  - At every step `k` in `0 .. L - 1`, the query token sits at sequence index `P - 1 + k` (where `P = B + L + 3`): at `k = 0` this is the second `[SEP]` (`position_id = 0`), and at `k >= 1` this is `o_{k-1}` (`position_id = k`), matching `x_k` (`TokenType.INPUT`, `position_id = k`) with zero offset, exactly as specified in [task.md](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/spec/task.md#L49-L59).
- **Zero causal or target leakage**:
  - In [build_cls_labelled_example](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/inputs.py#L13-L49), `example.input_ids` contains only `output = (o_0, ..., o_{L-2})` (note `o_{L-1}` and all `flag_k` are never placed into `input_ids` at all), and `labels` places `(o_k, int(flag_k))` at index `P - 1 + k`.
  - In [MultiHeadSelfAttention](file:///atelier/code/workshop/yessir/yessir/blocks.py#L102-L115), `F.scaled_dot_product_attention(q, k, v, is_causal=True)` applies a strict lower-triangular causal mask on `(seq_len, seq_len)`. Thus at query index `P - 1 + k`, the hidden state can attend only to indices `0 .. P - 1 + k` (`[BOS] alphabet [SEP] x [SEP] o_0 .. o_{k-1}`), never to `o_k` (which sits at `P + k` for `k < L - 1` and is absent for `k = L - 1`).
- **Right-padding invariance & `EmbeddingMode` parity**:
  - [collate](file:///atelier/code/workshop/yessir/yessir/batch.py#L59-L99) right-pads `input_ids` with `SpecialToken.PAD`, `token_type_ids` with `0`, and `position_ids` with `0` at indices `>= lengths[b]`. Because all real tokens precede all `PAD` tokens and `is_causal=True` prevents attending rightward, real token representations are strictly invariant to trailing padding (so no attention key-padding mask is needed).
  - Train (`SirYesSirClsDataset`), teacher-forced eval (`evaluate_cls`), and step-by-step generation (`greedy_generate_cls`) all call the exact same `build_example(..., embedding_mode=...)` function, and [SubspaceEmbedding.forward](file:///atelier/code/workshop/yessir/yessir/embedding.py#L119-L128) raises `ValueError` if the presence/absence of `token_type_ids` or `position_ids` ever disagrees with `use_token_type` or `d_position > 0`.

### 3.3 Model, multi-pass supervision, loss masking, and end-to-end config trace

- **Architecture & head mechanics**: Read [embedding.py](file:///atelier/code/workshop/yessir/yessir/embedding.py#L52-L156), [blocks.py](file:///atelier/code/workshop/yessir/yessir/blocks.py#L8-L136), [heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L55-L112), [model.py](file:///atelier/code/workshop/yessir/yessir/model.py#L23-L132), and [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L98-L268).
  - `SubspaceEmbedding` constructs orthogonal unit-norm `256`-d symbol one-hot, optional `16`-d `token_type` one-hot, optional `d_position`-d sinusoidal encodings (computed in `fp32` with base `256.0` and `1 / sqrt(d_position / 2)` scaling), and `d_scratch`-d zeros.
  - `ParallelClassificationHead` shares identical `RMSNorm` + bias-free `nn.Linear` parameters between `lengths=None` (`(B, T, 256)` for `SINGLE_PASS` training and `evaluate_cls`) and `lengths` provided (`(B, 256)` gathered at `lengths - 1` for `ALL_STEPS`, `RANDOM_STEP`, and `greedy_generate_cls`).
  - **Empirical loss & gradient equivalence probe**: Executed a single-problem `train_step` comparing `SINGLE_PASS` (batch of `1` sequence of length `P + L - 1` with `lengths=None` and `IGNORE_INDEX = -100` on `0 .. P - 2`) against `ALL_STEPS` (right-padded batch of `L = 4` sequences of lengths `P .. P + 3` read at `lengths - 1`) across all three `EmbeddingMode`s (`nope`, `token_type_nope`, `token_type_pe`). Scalar losses matched to `< 1e-6` (`11.250448` vs `11.250448` in `token_type_pe`) and maximum parameter gradient difference across the entire model was `<= 2.38e-7`.
- **Loss masking**:
  - In `SINGLE_PASS`, `labels` masks prompt indices `0 .. P - 2` with `(-100, -100)` and [collate_labelled](file:///atelier/code/workshop/yessir/yessir/batch.py#L144-L149) pads positions `>= len(item.labels)` with `IGNORE_INDEX = -100`. [parallel_classification_cross_entropy](file:///atelier/code/workshop/yessir/yessir/training.py#L143-L147) passes `ignore_index=IGNORE_INDEX` to `F.cross_entropy` for each head and sums the two mean cross-entropies, excluding all prompt and padded positions from the loss and gradients.

### 3.4 Evaluation, outer-loop rollout, and metrics (`evaluation.py`, `generation.py`, `metrics.py`)

- **Outer-loop generation (`greedy_generate_cls`)**: Read [generation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/cls/generation.py#L17-L74).
  - Calls `model.eval()` under `@torch.no_grad()`.
  - Starts from `output: list[Token] = []`, builds `build_example(alphabet_tokens, x_tokens, output, embedding_mode=embedding_mode)` at each step, runs `model` at `batch.lengths` (`lengths - 1`), decodes `o_k` and `flag_k` via `argmax`, stops immediately when `flag_k == SpecialToken.FLAG_FINISHED` (or after `len(x_tokens)` steps, where `x_tokens` is part of the problem prompt rather than a hidden reference answer), and appends the model's **own** predicted `o_k` (including any out-of-alphabet or special byte `0..255` without crashing) into `output` for step `k + 1`. Zero reference trajectory leakage exists.
- **Equivalence of teacher-forced `evaluate_cls` `exact_match` and free-running `greedy_generate_cls` `exact_match`**:
  - By induction on `k = 0 .. L - 1`: at `k = 0`, both `evaluate_cls` (at index `P - 1` under `is_causal=True`) and `greedy_generate_cls` (at `lengths - 1 = P - 1`) read the identical prompt prefix `[BOS] alphabet [SEP] x [SEP]`. If `(pred_o[0], pred_flag[0]) != (o_0, flag_0)`, both score the problem as a non-exact-match (`steps[0] != (o_0, flag_0)`). Otherwise `pred_o[0] == o_0` and `pred_flag[0] == flag_0` (`FLAG_CONTINUE` for `L > 1`, `FLAG_FINISHED` for `L == 1`), so for `L > 1` `greedy_generate_cls` appends `o_0` and step `k = 1` again sees the exact same prefix as teacher forcing. Thus `exact_match` is strictly identical up to `fp32` batch GEMM rounding.
- **Eval mode, batch isolation, and periodic evaluation**:
  - Both `evaluate_cls` and `greedy_generate_cls` call `model.eval()` (`train_step` restores `model.train()`), carry zero state across batches or calls, and `Transformer` contains no stateful buffers or dropout layers.
  - Periodic evaluation in [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/train_and_evaluate.py#L89-L126) re-slices a fresh iterator from `eval_dataset` at every checkpoint (evaluating on the exact same `num_eval_problems` problems every time) while keeping `train_stream = iter(train_dataset)` and `optimizer` persistent across chunks without perturbing training losses or weights.
  - [MetricsLogger](file:///atelier/code/workshop/yessir/yessir/metrics.py#L11-L42) sanitises `NaN`/`±inf` to `None` with `allow_nan=False`.
