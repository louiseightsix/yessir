### [Medium — Historical Provenance & Audit] All 6 legacy `sm_mh` runs in `results/sir_yes_sir/` ran a materially different task, architecture, loss scale, and teacher-forced evaluator from `HEAD` `cls`

- **Where**:
  - Historical runs: [2026-11-12-a13cc88-closing-filly](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-a13cc88-closing-filly/config.json#L1-L28) (`a13cc88`), [2026-11-12-86e46ea-communal-pigeon](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-86e46ea-communal-pigeon/config.json#L1-L28) (`86e46ea`), [2026-11-12-586f44d-champion-fox](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-champion-fox/config.json#L1-L28) (`586f44d`), [2026-11-12-586f44d-direct-ghost](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-direct-ghost/config.json#L1-L28) (`586f44d`), [2026-11-12-586f44d-innocent-monkey](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-innocent-monkey/config.json#L1-L28) (`586f44d`), and [2026-11-12-586f44d-proper-cub](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-proper-cub/config.json#L1-L28) (`586f44d`).
- **Verified code differences (`git show a13cc88:...` and `git show 586f44d:...` vs `HEAD`)**:
  1. **3-head output `(o_k, w_k, flag_k)` vs 2-head `(o_k, flag_k)`**: At `a13cc88` and `586f44d`, `reference_step` predicted an extra wrap-indicator symbol `w_k` (`s_1` if `i == B - 1` else `s_0`), using a 3-head `MultiTaskHead` (`num_classes=(256, 256, 256)`). `HEAD` `cls` predicts 2 heads `(o_k, flag_k)` (`num_classes=(256, 256)`).
  2. **`[STEP]` trigger token vs direct `[SEP]` / `o_{k-1}` queries**: At `a13cc88` and `586f44d`, `build_sm_example` appended `SpecialToken.STEP` (`[BOS] alphabet [SEP] x [SEP] o_0..o_{k-1} [STEP]`, with `TokenType.OUTPUT` `position_ids = 0..k` so `[STEP]` sat at `k`). At `HEAD`, `SpecialToken.STEP` is removed and `TokenType.OUTPUT` `position_ids` start at `1..k` so `[SEP]` (`0`) and `o_{k-1}` (`k`) serve directly as query positions.
  3. **Single-step (`all_steps`) training vs `single_pass` default**: At `a13cc88` and `586f44d`, `SirYesSirDataset` / `SirYesSirSmMhDataset` emitted `L` single-step examples per problem (`batch_size` steps from `~batch_size / L` problems per step). `HEAD` defaults to `ClsSupervision.SINGLE_PASS` (`L * batch_size` steps from `batch_size` problems per step).
  4. **Unnormalised summed 3-head loss vs per-head mean loss**: `multitask_cross_entropy` at `a13cc88`/`586f44d` summed CE across all 3 heads without dividing by `H` (explaining why step-1 `loss` in `train.jsonl` is `16.20`–`17.03`, i.e. `3 * ln(256) ≈ 16.64`), whereas `parallel_classification_cross_entropy` in [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L151) divides by `num_targets = 2` (`ln(256) ≈ 5.55`).
  5. **Teacher-forced evaluation and different metric definitions**: At `a13cc88` and `586f44d`, `evaluate_sm_mh` ran **teacher-forced** step batches rather than free-running rollout; `step_accuracy` required all 3 heads `(o_k, w_k, flag_k)` to match (vs `o_k` before halting at `HEAD`); and `halt_accuracy` was computed **per step** (`sum / (L * num_problems)`) rather than **per problem**—directly visible in [direct-ghost/eval.json](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-direct-ghost/eval.json#L4), which reports `"halt_accuracy": 0.9966666666666667` (`299 / 300` across `100` problems of length `L = 3`).
  6. **Uncontrolled `d_model` shrinkage across `EmbeddingMode`s**: At `586f44d`, `fixed_d_model` did not exist and non-PE modes required `d_position = 0` while keeping `d_scratch = 208`, so the 3-run ablation `innocent-monkey` (`token_type_pe`) -> `champion-fox` (`token_type_nope`) -> `direct-ghost` (`nope`) shrank `d_model` from `512` -> `480` -> `464`.
  7. **Dirty working trees & schema incompatibility**: Four of the six runs (`communal-pigeon`, `champion-fox`, `direct-ghost`, `innocent-monkey`) ran with `"git_dirty": true`, and `closing-filly` had `"variant": "sm_mh"` backfilled after `a13cc88`. ### [Low — Config Deserialisation Validation Gap] `SirYesSirConfig.from_dict` / `SirYesSirClsConfig.from_dict` lack `bool` and `_is_int` type checks, so string `"false"` in JSON silently evaluates as `True`

- **Where**:
  - [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L92-L156) (`SirYesSirConfig.__post_init__`)
  - [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L241-L260) (`SirYesSirClsConfig.__post_init__`)
  - Contrast with `eval_every` on [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L137-L144) and `_is_int` in [example.py](file:///atelier/code/workshop/yessir/yessir/example.py#L19-L21).
- **Concrete trigger**: Calling `SirYesSirClsConfig.from_dict({"resample_alphabet": "false"})` or passing `--config custom.json` containing `"fixed_d_model": "false"` (a JSON string rather than JSON boolean `false`). Because neither `resample_alphabet` nor `fixed_d_model` checks `isinstance(..., bool)`, Python's truthiness treats non-empty `"false"` as `True`: `iter_problems` resamples alphabets per problem instead of holding canonical order fixed, and `effective_d_scratch` keeps `d_model = 512` instead of shrinking, while `write_config_json` writes `"false"` into `config.json`. Likewise, `bool` values (`True`/`False`) pass `< 1` / `< 0` integer range checks on `n_layers`, `n_heads`, `x_length`, `d_scratch`, `seed`, etc. because `bool` subclasses `int`.
- **Impact**: CLI flags (`--no-resample-alphabet`, `--no-fixed-d-model`) and TUI edits produce real `bool`s and are unaffected; this only triggers if a user hand-writes a JSON file for `--config` with quoted booleans.

### [Low — Positional Encoding Edge-Case Trap] At the minimum allowed `d_position = 4` (`TOKEN_TYPE_PE`), `_SINUSOIDAL_BASE = 256.0` creates an exact period of `32 * pi ≈ 100.53` positions

- **Where**:
  - [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L248-L253) (`d_position >= 4` check in `SirYesSirClsConfig.__post_init__`)
  - [embedding.py](file:///atelier/code/workshop/yessir/yessir/embedding.py#L49) and [embedding.py](file:///atelier/code/workshop/yessir/yessir/embedding.py#L85-L106) (`_SINUSOIDAL_BASE = 256.0`, `_sinusoidal_positions`).
- **Concrete trigger**: Combining `d_position = 4` (permitted by `SirYesSirClsConfig` for [minimum-model-size.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/minimum-model-size.json#L1-L8)) with `alphabet_size > 100` (up to `240` in [alphabet-length.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/alphabet-length.json#L5)) or `x_length > 100` ([sequence-length.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/sequence-length.json#L5)).
  - At `d_position = 4` (`half_pos = 2`), `inv_freq = [256^0, 256^(-1/2)] = [1.0, 1/16]`. Because `1.0 = 16 * (1/16)` is an exact integer multiple, the entire 4-D sinusoidal vector `(sin(p), cos(p), sin(p/16), cos(p/16)) / sqrt(2)` is strictly periodic with period `32 * pi ≈ 100.531`.
  - Across valid alphabet/input positions `0..239`, positions separated by `201 ≈ 64 * pi = 201.062` (e.g. `position_id = 38` and `position_id = 239`, or `0` and `201`) nearly collide with cosine similarity `0.999038` (`L2` distance `0.0439`).
- **Impact**: Zero impact at default `d_position = 32` (slowest full cycle `2 * pi * 256^(15/16) ≈ 1,137.4` positions; max cosine similarity across `0..239` is `0.9409`, strictly between adjacent positions) or for `d_position >= 8` (period `128 * pi ≈ 402.1` > `240`), or for `d_position = 4` when `B, L <= 100`. Only affects `d_position = 4` if paired with `B > 100` or `L > 100`.

### Gaps in current test coverage
1. **End-to-end `run_sir_yes_sir_cls` with `supervision="all_steps"` and `supervision="random_step"`**: [test_run.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/tests/test_run.py) only exercises `SINGLE_PASS`; neither `all_steps` (including `batch_size % x_length != 0`) nor `random_step` is tested through `run_sir_yes_sir_cls` / `train_and_evaluate`.

6. **Malformed JSON types in `SirYesSirClsConfig.from_dict`**: [test_config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/tests/test_config.py#L174-L175) tests `eval_every=True`, without testing `bool` passed to other `int` fields or string `"false"` passed to `bool` fields (`resample_alphabet`, `fixed_d_model`).
