## 2. Findings (Suspected Bugs, Spec Mismatches, Silent Confounds, or Edge-Case Traps)

**Headline verdict: Zero High- or Medium-severity bugs were found, and no bug was found that can move `exact_match`, leak target tokens or ground-truth trajectory state, break causal or left-pad masking, or silently ignore a configuration parameter.** In particular, `exact_match == 1.0` on a problem holds if and only if the model's unassisted greedy rollout emits `(*gold_trace, EOS)` token-for-token.

Below are three **Low**-severity diagnostic edge cases in evaluation rollout parsing/budgeting (affecting secondary diagnostic metrics such as `halt_accuracy` or `address_accuracy` on already-failing rollouts) and two **Note**-level experimental/defensive observations.

### [Low] 1. Under `use_query_tokens=True`, a wrong `>= 5`-digit address at column `K` followed immediately by `[EOS]` (with zero query/value tokens) scores `halt_accuracy = 1.0`

- **Location**: `[evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/evaluation.py#L186-L220)` (`_parse_addressed_ar_rollout`).
- **Mechanism**: When `use_query_tokens=True` (`body_len = 4`), `truncated_query_body_eos` (`#L194-L201`) catches premature `[EOS]` on a wrong-address final segment only when at least one `[S]` or `[C]` token appears in `seg_tokens` (`first_query_idx is not None`). If at the final column `k == last_k` the model emits `[IDX]` followed by 5 or more wrong address symbols (for example on binary `B = 2` at `k = 16..20` in `id`, or `k = 16..40` in `extrap_len`) and immediately halts with `[EOS]` *before* emitting `[S]`, `o_K`, `[C]`, or `c_{K+1}`, then:
  - `valid_header_premature_eos` (`#L178-L185`) is `False` because the address does not match `expected_addr`;
  - `first_query_idx` (`#L186-L193`) is `None`, so `truncated_query_body_eos` is `False`;
  - `has_full_entry` (`#L202-L206`) evaluates `len(seg_tokens) >= 1 + body_len` (`5 >= 5` -> `True`);
  - `halt_ok` (`#L214-L220`) evaluates to `True`, scoring `halt_accuracy = 1.0` despite the missing 4-token `[S] o_K [C] c_{K+1}` body (contradicting `[addressed_ar.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/addressed_ar.md#L95)`: *"completing `K + 1` full segments without premature `[EOS]`"*).
- **Concrete trigger (verified via Python)**:
  ```python
  # Base 2, 17 steps (k = 0..16, addr(16) = b"00001"), use_query_tokens=True:
  # Columns 0..15 match; column 16 emits wrong 5-bit address b"10001" + EOS (no [S], o_16, [C], c_17).
  alpha, a, b = tuple(b"01"), tuple(b"1" * 16), tuple(b"1")
  steps = reference_add(alpha, a, b)
  emitted = [
      *build_addressed_ar_trace_tokens(steps[:16], alpha, use_query_tokens=True),
      int(AdditionToken.IDX), *b"10001", int(SpecialToken.EOS),
  ]
  preds = _parse_addressed_ar_rollout(
      emitted, alpha, num_steps=len(steps), step_order=StepOrder.SUM_FIRST, use_query_tokens=True
  )
  # preds[-1] -> StepPrediction(sum_digit=48, carry_out=49, syntax_ok=False, halt_ok=True, address_ok=False)
  # score_predictions -> exact_match=0.0, halt_accuracy=1.0, syntax_malformation=1.0
  ```
- **Impact on headline metrics & study claims**: **Does not affect `exact_match`, `step_accuracy`, `digit_accuracy`, `carry_accuracy`, `address_accuracy`, or `FirstErrorType`** (because `queries_ok` is `False`, forcing `syntax_ok = False` and `SYNTAX_MALFORMATION`). Can only inflate the diagnostic `halt_accuracy` in `eval_splits.json` / `eval.jsonl` when `use_query_tokens=True` and a rollout halts right after a `>= 5`-symbol wrong final address (primarily `B = 2` on `L >= 16`).

### [Low] 2. Zero-slack `max_tokens` rollout budget cuts off `[EOS]` or column `K` on carry-overflow problems whenever any earlier column emits a wider-than-reference address

- **Location**: `[evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/evaluation.py#L406-L413)` and `[generation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/generation.py#L121-L128)`, matching the formula in `[addressed_ar.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/addressed_ar.md#L83-L87)`.
- **Mechanism**: Both `rollout_addressed_ar` and `evaluate_addressed_ar` cap generation at `max_tokens = sum_{k=0..N} (1 + len(encode_address(k, alphabet)) + body_len) + 1`, where `N = max(L_a, L_b)`. On non-overflow problems (`K = N - 1`), there is one unused column's worth of slack (`1 + len(addr(N)) + body_len` tokens). However, on carry-overflow problems (`K = N`), the ground-truth trace plus `[EOS]` consumes 100% of `max_tokens` with zero slack. If the model predicts an over-wide address on any earlier column `0 .. K - 1` (spending `d >= 1` extra tokens in total), generation hits `max_tokens` before finishing column `K` + `[EOS]`:
  - `d == 1` cuts off `[EOS]`, forcing `ended_with_eos = False` and `halt_accuracy = 0.0` even if the model would have emitted `[EOS]` next.
  - `d >= 2` cuts into column `K`'s body/header, turning column `K`'s `step_accuracy` and `address_accuracy` from `True` to `False` purely from budget exhaustion.
- **Concrete trigger (verified via Python)**:
  - On `alphabet = b"01", a = b"1", b = b"1"` (`N = 1`, overflow `K = 1`, `num_steps = 2`, `max_tokens = 9`): if a model's greedy continuation is `[IDX, '0', '0', o_0, c_1, IDX, '1', o_1, c_2, EOS]` (10 tokens, `+1` extra address token on column `0`), `max_tokens = 9` stops at `c_2`, scoring `halt_accuracy = 0.0` (`step_accuracy = 0.5`, `address_accuracy = 0.5`). With a 3-token wrong address on column `0` (`d = 2`), `c_2` is cut off too, dropping both `step_accuracy` and `address_accuracy` on the problem from `0.5` to `0.0`.
- **Impact on headline metrics & study claims**: **Zero effect on `exact_match` or `FirstErrorType`** (any trace that over-extends an earlier column's address already has `exact_match = 0.0` and `FirstErrorType.SYNTAX_MALFORMATION` at that earlier column). Worth bearing in mind when interpreting diagnostic `address_accuracy` and `halt_accuracy` on `extrap_len` in `[embedding-modes-length.json](file:///atelier/code/workshop/yessir/studies/addition/embedding-modes-length.json#L5)` if a model systematically emits over-wide addresses on overflow problems.

### [Low] 3. Left-anchored truncation checks in `_parse_addressed_ar_rollout` only trigger on `[EOS]` at `is_last_seg`, mis-slicing valid multi-digit headers when truncated mid-body by `[IDX]` or `max_tokens`

- **Location**: `[evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/evaluation.py#L178-L206)` and `[evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/evaluation.py#L224-L239)`.
- **Mechanism**: `_parse_addressed_ar_rollout` normally extracts `pred_addr = tuple(seg_tokens[:-body_len])` from the right (`#L225`), relying on `valid_header_premature_eos` (`#L178-L185`) and `truncated_query_body_eos` (`#L194-L201`) to avoid splitting a valid multi-digit address (`k >= B`, `len(addr(k)) >= 2`) when the body is incomplete. Because both guards require `is_last_seg and ended_with_eos`, they do not fire when a multi-digit segment's body is cut short by:
  1. **The next `[IDX]` (`is_last_seg = False`)**: e.g. on `alphabet = b"01", a = b"111", b = b"1"` (`4` steps, `use_query_tokens=True`), if column `2` (`addr(2) = b"01"`) emits `[IDX, '0', '1', [S], o_2, [C]]` (missing `c_3`) and immediately opens column `3` `[IDX, '1', '1', [S], o_3, [C], c_4, EOS]`, `seg_tokens` at `k = 2` has length `5 >= 1 + 4`, so `has_full_entry = True`, `pred_addr` is sliced as `('0',) != ('0', '1')` (`address_ok = False` despite `[IDX] + addr(2)` having been emitted), and `halt_ok = True` (`halt_accuracy = 1.0` despite the incomplete segment `2`).
  2. **Hitting `max_tokens` (`ended_with_eos = False`)**: e.g. on `alphabet = b"01", a = b"11", b = b"01"` (`3` steps, `use_query_tokens=False`, `max_tokens = 14`), if column `0` consumes 6 tokens and column `2` (`addr(2) = b"01"`) hits `max_tokens` right after `[IDX, '0', '1', o_2]`, `ended_with_eos = False` skips `valid_header_premature_eos`, slicing `pred_addr = ('0',)` and scoring `address_ok = False` and `digit_ok = False` on column `2`.
- **Impact on headline metrics & study claims**: **Zero effect on `exact_match` or `step_accuracy`** (in both cases `c_{k+1}` was missing, so `step_accuracy` on column `k` and `exact_match` on the problem are `0` regardless). Affects only diagnostic `address_accuracy` / `digit_accuracy` / `halt_accuracy` on mid-body truncated multi-digit segments.

### [Note] 4. Token-mean cross-entropy weights `[IDX]` + `addr(k)` equally with `(o_k, c_{k+1})`, affecting `train.jsonl` loss scale and per-base gradient weight

- **Location**: `[inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/inputs.py#L94-L96)` and `[training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L154-L186)` (`next_token_cross_entropy`), noted alongside `[variants-comparison.json](file:///atelier/code/workshop/yessir/studies/addition/variants-comparison.json#L5)`.
- **Detail**: `next_token_cross_entropy` computes a flat mean over all non-`IGNORE_INDEX` targets in the batch. On a 20-column trace (`k = 0..19`, `use_query_tokens=False`), `ar` supervises `41` tokens (`40` arithmetic + `1` `[EOS]`), whereas `addressed_ar` supervises `91` tokens in base `10` (`50` `[IDX]`/`addr(k)` + `40` arithmetic + `1` `[EOS]`, `2.22x`) and `131` tokens in base `2` (`90` `[IDX]`/`addr(k)` + `40` arithmetic + `1` `[EOS]`, `3.20x`).
- **Interpretation note**: (1) Once deterministic counter transitions (`[IDX] addr(k)`) reach near-zero loss early in training, `addressed_ar`'s `train.jsonl` `loss` (`nats / target`) is diluted by roughly `2.2x–3.2x` relative to `ar` at identical `(o_k, c_{k+1})` cross-entropy, while `tokens_seen` accumulates `2.2x–3.2x` faster per column transition; (2) within mixed-base batches (`bases="2,4,8,10"`), binary examples contribute ~`1.44x` as many supervised target positions as equal-length decimal examples. Evaluation metrics (`exact_match`, `step_accuracy`, etc.) are completely unaffected.

## 3. What Was Verified and Found Sound

1. **Ground-truth oracle (`[reference.py](file:///atelier/code/workshop/yessir/experiments/addition/reference.py#L38-L186)`)**:
   - Verified `LSD -> MSD` indexing, unpadded unequal-length operands (`0` substitution for `k >= L_a` or `k >= L_b`), carry-in/carry-out bounds (`total <= 2 * B - 1`, so `c_{k+1}` is strictly `s_0` or `s_1`), halting condition (`k >= max(L_a, L_b) - 1 and c_{k+1} == s_0`), single-digit `0 + 0` (`K = 0`), full carry-ripple overflow (`K = max(L_a, L_b)` with `o_K = s_1, c_{K+1} = s_0, flag_K = FLAG_FINISHED`), smallest (`B = 2`) and largest (`B = 240`) bases, and arbitrary non-ASCII symbol orders.
2. **Base-`B` address encoding (`[inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L123-L147)`) & `extrap_len` slot analysis**:
   - `encode_address(j, alphabet)` maps `j = 0 -> (s_0,)` and `j > 0 -> (s_{j % B}, s_{(j // B) % B}, ...)` (`LSD -> MSD`, no trailing `s_0` padding) using the problem's own `alphabet` symbols (random 240-byte, canonical, or permuted canonical).
   - Hand-verified every unseen-width and unseen-MSD claim in `[addressed_ar.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/addressed_ar.md#L19-L24)` and `[embedding-modes-length.json](file:///atelier/code/workshop/yessir/studies/addition/embedding-modes-length.json#L5)` across `B = 2, 4, 8, 10, 12` for `L = 1..20` (plus overflow `k = 20`) vs. `L = 21..40`.
   - Hand-verified the expected column transition ratio (`E[K + 1] = 13.90`, `~14x`, and `64 / E[K + 1] = 4.6`, `~4.5`) cited in `[variants-comparison.json](file:///atelier/code/workshop/yessir/studies/addition/variants-comparison.json#L5)` and `[step-sampling.json](file:///atelier/code/workshop/yessir/studies/addition/step-sampling.json#L5)`.
3. **Problem sampling, zero-preamble mode, and train/eval split disjointness (`[inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L352-L504)`, `[config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L338-L405)`)**:
