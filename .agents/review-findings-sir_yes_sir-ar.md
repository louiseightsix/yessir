## 2. Findings (Suspected Bugs, Spec Mismatches, Silent Confounds, or Edge-Case Traps)

**Headline summary**: At current `HEAD`, **zero headline-moving correctness bugs, target/mask leaks, teacher-forced evaluation leaks, or silent config no-ops were found** in the `ar` variant of `sir_yes_sir`. Every recorded historical `ar` run in `results/sir_yes_sir/` predates the current pure-LM task and free-running rollout evaluator, and is already properly quarantined with `OUTDATED: built against draft spec` in its `README.md` (and unreferenced by `studies/sir_yes_sir/*.json`, all of which currently have `"runs": []`). ### 2.1 [Medium — Historical Runs Only, Mitigated by `OUTDATED:` Markers] Historical `ar` runs in `results/sir_yes_sir/` (`586f44d`, `86e46ea`, `1eb53a1`) ran a different task, input representation, and teacher-forced evaluator than current `HEAD`

- **Where**: All 8 `"variant": "ar"` directories under `results/sir_yes_sir/` (e.g. [config.json](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-merry-serval/config.json#L1-L29), [eval.json](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-merry-serval/eval.json#L1-L5), [README.md](file:///atelier/code/workshop/yessir/results/sir_yes_sir/2026-11-12-586f44d-merry-serval/README.md#L1)) vs current [ar.md](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/spec/variants/ar.md#L1-L38), [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L218-L221), and [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/evaluation.py#L122-L211).
- **What differed at `586f44d` / `86e46ea` / `1eb53a1`** (verified via `git show 586f44d:...`; `experiments/sir_yes_sir/` and `yessir/` were identical across `586f44d`, `86e46ea`, and `1eb53a1`):
  1. **Different target trace (`3 * L` tokens with wrap token `w_k` and `FLAG_*` instead of `L + 1` tokens ending in `[EOS]`)**: Each step `k` emitted 3 tokens `(o_k, w_k, flag_k)` (`step_order="out_first"`) or `(w_k, o_k, flag_k)` (`step_order="wrap_first"` in `assured-longhorn`), ending with `FLAG_FINISHED` rather than `[EOS]`.
  2. **Harnessed side-channel embeddings instead of pure LM**: All 8 historical `ar` runs used `embedding_mode="token_type_pe"` (`use_token_type=True`, `d_position=32` or `8`, `d_scratch=208` or `16`), feeding `token_type_ids` (`TokenType.OUTPUT = 3`) and sequential output `position_ids = 0, 1, ..., 3L - 1` into `SubspaceEmbedding`. Current `HEAD` (`be36867` onward) restricts `ar` to `input_ids` only (`use_token_type=False, d_position=0, d_scratch=256`). (Note: `TiedIdentityHead` at `586f44d` had the exact same gain-free `RMSNorm(d_model, gain=False)[:, :, :256]` computation as current `SubspaceLMHead`.)
  3. **Teacher-forced `evaluate_ar` and per-step `halt_accuracy` inflation prior to `be36867`**: At `586f44d`–`1eb53a1` (and at `2db3181` prior to `be36867`), `evaluate_ar` ran a single teacher-forced forward pass over `collate_labelled(chunk)` rather than free-running autoregressive rollout. While `exact_match` under greedy argmax is invariant to teacher forcing on fixed-length traces when every target token matches, `step_accuracy` on imperfect models (`climbing-pig`, `live-moth`, `merry-serval`, `sharp-mammal`, `teaching-gazelle`) conditioned steps `k >= 1` on ground-truth history rather than the model's own predictions and did not stop on premature halting. Furthermore, at `586f44d` `halt_accuracy` was computed **per step** (`halt_ok_count / total_steps`) rather than **per problem** (`halt_ok_count / num_problems`), allowing a model that always predicted `FLAG_CONTINUE` to score `(L - 1) / L`.
  4. **Dirty working trees & config incompatibility**: Five of the eight historical `ar` runs (`climbing-pig`, `live-moth`, `merry-serval`, `sharp-mammal`, `refined-crow`) recorded `"git_dirty": true`. Passing any historical `ar` `config.json` via `--config` to current `SirYesSirArConfig` raises `TypeError` on the removed keys (`embedding_mode`, `d_position`, `steps`, `step_order`).
- **Impact**: **None on current claims**, provided the `OUTDATED: built against draft spec` annotations in every `results/sir_yes_sir/*/README.md` continue to be respected and none of those historical runs is linked into `studies/sir_yes_sir/*.json`.

### 2.3 [Low — Spec/Docstring Wording Ambiguity] `wrap_around_accuracy` prose can be read as conditioning the denominator on steps reached before halting, whereas `evaluate_ar` includes all reference wrap-around steps

- **Where**: [task.md](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/spec/task.md#L79) and [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/evaluation.py#L24-L27) vs [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/evaluation.py#L191-L199) (and [test_evaluation_and_generation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/tests/test_evaluation_and_generation.py#L675-L705)).
- **Details**: `task.md` defines `wrap_around_accuracy` as *"fraction of reference steps with `x_k == s_{B-1}` (ground-truth successor `s_0`) reached before halting where the predicted symbol equals `s_0`"*. Unlike `step_accuracy` on [task.md](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/spec/task.md#L77) (which explicitly writes *"where step `k` was reached before halting and the predicted symbol matches `o_k`. Steps missed after a premature halt count as incorrect against the `L` denominator"*), the phrasing for `wrap_around_accuracy` reads as if unreached post-halt steps are excluded from `wrap_steps`. In `evaluate_ar`, `wrap_steps` increments unconditionally for every `k` in `0 .. n_steps - 1` with `x[k] == alphabet[-1]`, and `wrap_ok_count` requires `k < len(symbol_preds) and symbol_preds[k] == targets[k]`.
- **Impact**: The code's behaviour is **more sound** than the ambiguous reading (excluding unreached steps from the denominator would let a model that halts prematurely after solving step 0 achieve `100%` `wrap_around_accuracy`). Clarifying the prose to match `step_accuracy`'s wording would remove the ambiguity.

### 2.4 [Low — Standalone API Validation Gaps] `evaluate_ar`, `parse_prompt_prefix`, and `reference_step` accept malformed synthetic inputs or raise `IndexError` when called outside `SirYesSirArDataset`

- **Where**:
  1. `_validate_ar_item` in [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/evaluation.py#L16-L35) and `evaluate_ar` in [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/evaluation.py#L153-L199).
  2. `parse_prompt_prefix` in [evaluation.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/evaluation.py#L36-L57).
  3. `reference_step` in [reference.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/reference.py#L36-L46).
- **Concrete triggers** (verified via `.venv-linux/bin/python`):
  1. **Mismatched `len(x)` vs `len(targets) - 1` in `evaluate_ar`**: `evaluate_ar` computes `n_steps = len(targets) - 1` and `prefix_len = len(item.example) - n_steps`, then parses `(alphabet, x) = parse_prompt_prefix(prefix.input_ids)` without asserting `len(x) == n_steps`. On `Example(input_ids=(BOS, 48, 49, SEP, 48, SEP, 49, 48, 49))` with `labels = (-100,) * 5 + (49, 48, 49, EOS)` (`len(x) == 1`, `n_steps == 3`), both validators pass and `x[k]` crashes with `IndexError: tuple index out of range` at line 192 (or silently ignores `x[n_steps:]` when `len(x) > n_steps`).
  2. **Non-contiguous `IGNORE_INDEX` positions in `_validate_ar_item`**: `_validate_ar_item` collects `[t for t in item.labels if isinstance(t, int) and t != IGNORE_INDEX]` without checking that the supervised labels occupy the contiguous suffix `item.labels[-len(target_tokens):]`. Passing `labels = (49,) + (-100,) * 6 + (48, EOS)` on a length-9 example (`B = 2, L = 2`) silently passes validation and evaluates `[49, 48, EOS]` as the target sequence.
  3. **Single-symbol alphabet in `parse_prompt_prefix` and duplicate/non-symbol bytes in `reference_step`**: `parse_prompt_prefix` only checks `if not alphabet or not x:` (`len >= 1`) rather than `len(alphabet) >= 2`. Standalone `reference_step(b"00", b"0", 0)` checks `len(alphabet) >= 2` and `alphabet.index(x[k])` without rejecting duplicate symbols in `alphabet` or bytes outside `SYMBOL_RANGE` (`0x00..0xEF`), returning `(48, SpecialToken.FLAG_FINISHED)`.
- **Impact**: **Zero impact on standard runs**, because `SirYesSirArDataset` and `build_ar_labelled_example` always route through `validate_problem` -> `create_alphabet` and construct contiguous suffix labels of exact length `len(x) + 1`. Only affects custom callers constructing `LabelledExample`s or calling `reference_step` directly.

### 2.5 [Low — Programmatic `from_dict` Type Guards] `SirYesSirConfig.__post_init__` rejects `bool` on `eval_every` but not on other numeric/boolean fields

- **Where**: [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L92-L157) (and standalone inspect CLI in [dataset.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/dataset.py#L57-L64)).

By contrast, `eval_every` on lines 137–141 explicitly checks `isinstance(self.eval_every, bool) or not isinstance(self.eval_every, int)`. ### 2.6 [Note — Study Design & Operational Nuances] `SubspaceLMHead` effective temperature scaling with `d_scratch`, fixed `d_ff = 1376`, `tokens_seen` vs problem-count accounting, `--no-save` logging, and TUI duplicate checks

- **Where**: [heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L42-L53), [config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L68-L70), [cls-vs-ar.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/cls-vs-ar.json#L5), [minimum-model-size.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/minimum-model-size.json#L5), [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/train_and_evaluate.py#L116-L142), and [artefacts.py](file:///atelier/code/workshop/yessir/yessir/artefacts.py#L179-L207).
- **Details**:
  1. **`SubspaceLMHead` logit ceiling & step-0 self-copy bias vary with `d_model` (`256 + d_scratch`)**: Because `SubspaceLMHead` applies gain-free `RMSNorm(d_model, gain=False)` across all `d_model` coordinates and slices `[:, :, :256]`, a hidden state concentrated on symbol coordinates has L2 norm `sqrt(d_model)` (`16.0` at `d_scratch = 0` vs `22.63` at `d_scratch = 256` vs `32.0` at `d_scratch = 768`), while at step 0 isotropic residual noise across `d_scratch` dilutes the input one-hot self-copy spike (`step0_loss ≈ 10.78` at `d_scratch = 0`, `7.00` at `d_scratch = 256`, `5.89` at `d_scratch = 768`). Meanwhile, any nonzero norm left in the scratchpad coordinates `256 .. d_model - 1` at the final layer reduces the norm available to the `0..255` logit slice. This is an inherent property of parameter-free `SubspaceLMHead` (and self-copy bias is documented in [heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L30-L40)), worth bearing in mind when sweeping `d_scratch` in `minimum-model-size`.
  2. **`d_ff` defaults to a fixed `1376` rather than scaling with `d_model`**: Sweeping `d_scratch` down in `SirYesSirArConfig` leaves `d_ff = 1376` unless `--d-ff` is explicitly passed (documented in [model.py](file:///atelier/code/workshop/yessir/yessir/model.py#L20-L25)).
  3. **`tokens_seen` in `cls-vs-ar`**: At equal `batch_size` and optimiser step `s`, `ar` and `cls` (`single_pass`) observe the exact same `s * batch_size` `(alphabet, x)` problems, whereas `tokens_seen` is `s * batch_size * (L + 1)` in `ar` vs `s * batch_size * (2 * L)` in `cls` because `cls` counts `L` deterministic halting flags per problem while `ar` counts one `[EOS]` token (explicitly noted in Caveat 3 of [cls-vs-ar.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/cls-vs-ar.json#L5)). Comparing sample efficiency solely per `tokens_seen` therefore shifts `cls` rightward by `2L / (L + 1)` (`1.5x` at `L = 3`, approaching `2x` at large `L`) relative to distinct problems seen.
  4. **`wrap_around_accuracy` omitted under `--no-save`**: In [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/train_and_evaluate.py#L116-L142), `wrap_around_accuracy` is written only to `eval.jsonl` (`splits.id.wrap_around_accuracy`) and is neither printed to stdout nor included in the returned `eval_results` dict, so `--no-save` runs discard it.
  5. **`load_existing_run_configs` does not filter `OUTDATED:` / `FLAWED:` runs**: [artefacts.py](file:///atelier/code/workshop/yessir/yessir/artefacts.py#L179-L207) loads all `results/<experiment>/*/config.json` files regardless of `README.md` status markers; in the TUI ([tui.py](file:///atelier/code/workshop/yessir/yessir/tui.py#L312-L338)) re-running a config whose prior run was marked `FLAWED:` or `OUTDATED:` (under the current schema) triggers a soft confirmation prompt rather than ignoring superseded runs.

## 3. What Was Verified and Found Sound

1. **Ground-truth reference rule & byte-0 safety** ([reference.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/reference.py#L14-L56), [vocab.py](file:///atelier/code/workshop/yessir/yessir/vocab.py#L38-L48), [special_tokens.py](file:///atelier/code/workshop/yessir/yessir/special_tokens.py#L6-L20)):

3. **Sequence layout, pre-shifted labels, and zero answer leakage** ([inputs.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/variants/ar/inputs.py#L14-L42), [batch.py](file:///atelier/code/workshop/yessir/yessir/batch.py#L181-L234), [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L154-L186)):
   - For prefix `[BOS] s_0..s_{B-1} [SEP] x_0..x_{L-1} [SEP]` of length `P = B + L + 3`, `build_ar_labelled_example` builds `Example(input_ids=prefix + (o_0, ..., o_{L-1}))` of length `P + L` (`token_type_ids=None`, `position_ids=None`) and `labels = (-100,) * (P - 1) + (o_0, ..., o_{L-1}, EOS)` of length `P + L`.
   - At index `P - 1` (second `[SEP]`), causal self-attention (`is_causal=True`) sees `0 .. P - 1` (prompt only) and predicts `o_0`; at index `P - 1 + k` (`1 <= k < L`, token `o_{k-1}`), it sees `prefix + o_0..o_{k-1}` and predicts `o_k`; at index `P + L - 1` (`o_{L-1}`), it sees `prefix + o_0..o_{L-1}` and predicts `EOS`. `[EOS]` never appears in `input_ids`. Right-padded positions (`>= length`) cannot be attended to by earlier positions and are masked with `IGNORE_INDEX = -100` in `collate_labelled`.
