## 2. Medium-Severity Issues

### M1. `addition` — `prior_intrusion` misses end-to-end canonical-order fallback on `permuted`

- **Scope**: All 6 `addition` variants; directly affects diagnostic interpretation in [prior-override.json](file:///atelier/code/workshop/yessir/studies/addition/prior-override.json#L1-L8) and [step-order.json](file:///atelier/code/workshop/yessir/studies/addition/step-order.json#L1-L8).
- **Location**: `_classify_value_mismatch` in [evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/evaluation.py#L85-L109) and [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L162-L169).
- **Problem**:
  `_classify_value_mismatch` implements the exact rule in `spec/task.md` §3:
  ```python
  digit_value = alphabet.index(expected_token)
  if pred_token == SymbolSet.HEX[digit_value]:
      return FirstErrorType.PRIOR_INTRUSION
  ```
  Here `digit_value` is `(val_prompt(a_k) + val_prompt(b_k) + val_prompt(c_k)) % B` (or `// B`), computed under the **prompt's** permuted alphabet. Checking `pred_token == SymbolSet.HEX[digit_value]` only detects an *output-only* canonical substitution (reading `a_k, b_k` via the permuted prompt alphabet, then indexing `SymbolSet.HEX` at output).

  A model trained at `p_prior = 1.0` that memorised canonical ASCII numerals ignores the prompt's `alphabet` on **both** inputs and outputs, computing `reference_add(SymbolSet.HEX[:B], a, b)`. Because `total_canon % B != total_prompt % B` on most columns, `_classify_value_mismatch` labels most canonical-fallback predictions as `procedural_error` rather than `prior_intrusion`.
- **Verified numbers** (evaluating a 100% canonical-memorising oracle `reference_add(SymbolSet.HEX[:B], p.a, p.b)` over 1,000 `permuted` problems per base at `eval_seed = 999`):
  - **Under `sum_first` (and `cls` / `step_fork`)**: `prior_intrusion / (prior_intrusion + procedural_error)` is **`0.253` in `B = 3`** (half the `1 / (B - 1) = 0.500` chance baseline), **`0.294` in `B = 4`** (below `0.333` chance), **`0.187` in `B = 8`** (vs `0.143` chance), and **`0.129` in `B = 10`** (barely above `0.111` chance) — classifying `73%–87%` of canonical fallbacks as `procedural_error` because fixed-point agreements selectively deplete `prior_intrusion` at column `0`.
  - **Under `carry_first`**: because outgoing carry `c_1` is binary (`0` or `1`), roughly half of column-`0` pairs overflow under neither alphabet (`c_1_canon == '0' == HEX[0]` and `v_carry_prompt == 0`), hitting `pred_token == SymbolSet.HEX[0]` whenever `alphabet[0] != '0'`. On the **exact same** canonical-fallback predictions in `B = 10`, `prior_intrusion` jumps **`3.8x`** from `0.128` (`sum_first`) to **`0.487`** (`carry_first`, share `0.490`).
- **Impact**: Headline `permuted_exact_match` (`0.2%–2.4%`) and `permuted_step_accuracy` are completely unaffected, but comparing `prior_intrusion / (prior_intrusion + procedural_error)` against `1 / (B - 1)` in `prior-override` would miss end-to-end canonical fallback under `sum_first` and confound `sum_first` vs `carry_first`.

### L1. `addition/addressed_ar` — Three diagnostic edge cases in rollout parsing and `max_tokens` budgeting

- **Location**: [addressed_ar/evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/evaluation.py#L178-L239), [addressed_ar/evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/evaluation.py#L406-L413), and [addressed_ar/generation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_ar/generation.py#L121-L128).
- **Details** (none affects `exact_match`):
  1. **Wrong `>= 5`-symbol final address + immediate `[EOS]` under `use_query_tokens=True` scores `halt_accuracy = 1.0`** (`evaluation.py#L186-L220`): `truncated_query_body_eos` requires `first_query_idx is not None`. At `k == last_k` (e.g. `B = 2, k >= 16`), emitting `[IDX]` + `>= 5` wrong address symbols + `[EOS]` with zero `[S]`/`[C]` tokens satisfies `len(seg_tokens) >= 1 + body_len` (`5 >= 5`), setting `has_full_entry = True` and `halt_ok = True` despite omitting `[S] o_K [C] c_{K+1}` (`syntax_ok` is still `False`).
  2. **Left-anchored truncation guards only fire on `[EOS]` at `is_last_seg`** (`evaluation.py#L178-L206`, `#L224-L239`): `valid_header_premature_eos` and `truncated_query_body_eos` both require `is_last_seg and ended_with_eos`. When a multi-digit column (`k >= B`) emits a valid `[IDX] + addr(k)` header whose body is truncated by the next `[IDX]` (`is_last_seg = False`) or by `max_tokens` (`ended_with_eos = False`), `_parse_addressed_ar_rollout` falls back to right-slicing `seg_tokens[:-body_len]`, splitting `addr(k)` (`address_ok = False`, and `halt_ok = True` on mid-trace `[IDX]` truncation if total segment count equals `K + 1`).
  3. **Zero-slack `max_tokens` ceiling on carry-overflow problems (`K = max(L_a, L_b)`)** (`evaluation.py#L406-L413`, `generation.py#L121-L128`): on overflow problems, the reference trace + `[EOS]` consumes 100% of `max_tokens`. Any earlier column that predicts an over-wide address (`d >= 1` extra tokens) hits `max_tokens` before `[EOS]` (`d == 1`, zeroing `halt_accuracy`) or inside column `K` (`d >= 2`, zeroing column `K`'s `step_accuracy` and `address_accuracy`).

### L3. `addition` — Unseen byte-token traps when slicing `symbol_pool_size` on `SymbolSet.ALL` or training at `p_prior = 1.0` with OOD bases

- **Location**: [addition/config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L180-L215), [addition/config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L358-L405), and [addition/inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L426-L438).
- **Triggers**:
  1. `SymbolSet.ALL` starts at `0x00`, whereas canonical `SymbolSet.HEX` numerals sit at ASCII `0x30..0x39, 0x41..0x46`. Setting `symbol_set="all"` with `symbol_pool_size <= 57` (e.g. `symbol_pool_size=20` or `4`, `p_prior=0.0`) excludes `SymbolSet.HEX[:max_train_base]` from `config.symbol_pool`, yet `eval_permuted_canonical=True` stays active without raising and evaluates `permuted` on unseen ASCII numeral byte tokens whose Layer-0 one-hot input columns received zero gradient updates during training (and `0 < p_prior < 1` places canonical and random problems in disjoint byte ranges).
  2. At `p_prior = 1.0` with default `eval_ood_bases="3,12"`, training sees only the 10 bytes `b"0123456789"` while `ood_base3` and `ood_base12` (`p_prior = 0.0`) draw random alphabets from all 240 bytes of `SymbolSet.ALL` (230 untrained token embeddings / negatively pushed `cls` head rows).

### L4. `addition` & `sir_yes_sir` — Config canonicalisation, `fixed_d_model` traps, and `from_dict` type-guard gaps

- **Location**: [addition/config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L261-L268), [addition/config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L451-L495), [addition/config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L556-L571), [sir_yes_sir/config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L92-L157), [sir_yes_sir/config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L241-L280), and [addition/inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L449-L457).
- **Sub-items**:
  1. **`fixed_d_model=False` is a silent no-op under `embedding_mode="token_type_pe"`** (`AdditionStepConfig` and `SirYesSirClsConfig`): unlike `d_position != 32` under non-PE modes and `p_terminal != 0.2` under `all_steps=True`, `fixed_d_model=False` under `token_type_pe` produces the exact same `effective_d_scratch` as `True` while serialising a distinct `config.json` that bypasses exact-dict duplicate detection.
  2. **`--d-scratch 0` under `nope` / `token_type_nope` (including default `addressed_step_ar`) allocates `effective_d_scratch = 48` (`d_model = 304`) unless `--no-fixed-d-model` is passed**: `AdditionAddressedStepArConfig` defaults to `embedding_mode="nope"` while inheriting `d_scratch=208, d_position=32, fixed_d_model=True`.   3. **`p_chain` / `eval_p_chain` silent no-op when `max_length == 1`** (and `eval_extrap_max_length=None`): `n_shared = min(len_a, len_b) >= 2` never holds, yet non-default `p_chain` is accepted without error.

### L5. `yessir/embedding.py` — Exact `32 * pi ≈ 100.53` positional period at `d_position = 4` under `_SINUSOIDAL_BASE = 256.0`

- **Location**: [embedding.py](file:///atelier/code/workshop/yessir/yessir/embedding.py#L49), [embedding.py](file:///atelier/code/workshop/yessir/yessir/embedding.py#L85-L106), [sir_yes_sir/config.py](file:///atelier/code/workshop/yessir/experiments/sir_yes_sir/config.py#L248-L253), and [addition/config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L457-L462).
- **Mechanism**: At the minimum allowed `d_position = 4` (`half_pos = 2`), `inv_freq = [256^0, 256^(-1/2)] = [1.0, 1/16]`. Because `1.0 = 16 * (1/16)` is an exact integer multiple, the 4-D sinusoidal encoding is strictly periodic with period `32 * pi ≈ 100.53` positions (`cos_sim = 0.9990` between positions `38` and `239` if `d_position = 4` is combined with `B > 100` in [alphabet-length.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/alphabet-length.json#L5) or `L > 100` in [sequence-length.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/sequence-length.json#L5)). Unaffected at `d_position >= 8` (period `>= 402.1 > 240`) or when `B, L <= 100`.

## 4. Experimental Confounds & Operational Notes for Studies

1. **Deterministic overflow shortcut at `k = 20` in `B = 10` on `extrap_len`** (`addressed_step_ar` and `addressed_ar`, [embedding-modes-length.json](file:///atelier/code/workshop/yessir/studies/addition/embedding-modes-length.json#L5)): when training on `L_a, L_b <= 20`, operand addresses `0..19` in base `10` only ever place `s_1` in the `10^1` slot. Symbol `s_2` appears in the `10^1` slot *exclusively* on the carry-overflow column `k = 20` (`addr(20) = (s_0, s_2)`), where `a_20` and `b_20` are absent and the target is `100%` deterministically `(s_1, s_0, FLAG_FINISHED)` — directly conflicting with non-overflow columns `k = 20..29` on `extrap_len` (`L = 21..40`).
2. **Carry-chain injection start-column asymmetry & single-operand tails** ([addition/inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L449-L458)): at the carry-originating column `i`, drawing `a_vals[i]` uniformly from `1 .. B - 1` and then `b_vals[i]` from `B - a_vals[i] .. B - 1` weights `(u, v)` by `1 / ((B - 1) * u)` (`E[a_i] < E[b_i]` for `B >= 3`, e.g. `(1, 9)` is `9x` more likely than `(9, 1)` in base `10`), and chains are restricted to `min(len_a, len_b)` (leaving single-operand tail carries at their natural `(1 / B)^d` rate).
3. **Capacity, readout, and compute differences across variants**:
   - `d_ff` stays fixed at `1376` when shrinking `d_model` unless `--d-ff` is passed explicitly ([model.py](file:///atelier/code/workshop/yessir/yessir/model.py#L20-L25)).
   - Under `token_type_pe` at `d_scratch = 0`, harnessed variants (`cls`, `step_fork`, `step_ar`) retain `+48` non-scratch dims (`d_model = 304`, `+23.2%` block params vs `ar` at `d_model = 256`).
   - `ParallelClassificationHead` (`cls`) adds `+393,728` (`addition`) / `+262,656` (`sir_yes_sir`) parameters at `d_model = 512` (`+196,864` / `+131,328` at `d_model = 256`) relative to parameter-free `SubspaceLMHead`, while `SubspaceLMHead` scales its logit ceiling as `sqrt(d_model)` and starts with step-0 self-copy bias ([heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L30-L53)).
   - Relative to `cls`, `step_fork` increases sequence length by `+1` (`OUTPUT` `position_ids = 0..k-1` vs `1..k` in `cls`) and runs `3x` forward/backward FLOPs per optimiser step (compare by `step` or `tokens_seen`, not `elapsed_sec`).
4. **Logged `loss`, `tokens_seen`, `elapsed_sec`, and evaluation chunking**:
   - `ar --use-query-tokens` (~`1.97x` targets, ~`0.51x` `nats / target` loss) and `addressed_ar` (`2.2x–3.2x` targets, with `B = 2` having ~`1.44x` more target tokens per column than `B = 10`) supervise deterministic query/address tokens alongside `(o_k, c_{k+1})`.
   - In [cls-training-passes.json](file:///atelier/code/workshop/yessir/studies/sir_yes_sir/cls-training-passes.json#L5), at equal `tokens_seen`, `random_step` sees `L` times as many distinct `(alphabet, x)` problems as `single_pass` and `all_steps` (`tokens_seen / 2` vs `tokens_seen / (2 * L)`), and `sir_yes_sir`'s `eval.jsonl` logs `step` without `tokens_seen`.
   - `train.jsonl` `elapsed_sec` includes mid-training `eval_every` wall time; `sir_yes_sir` `--no-save` omits `wrap_around_accuracy` from stdout and `eval_results`; `load_existing_run_configs` ([artefacts.py](file:///atelier/code/workshop/yessir/yessir/artefacts.py#L179-L207)) includes `OUTDATED:`/`FLAWED:` runs in TUI duplicate prompts; and `evaluate_step_ar` slices strictly by `batch_size` without `MAX_EVAL_CHUNK_TOKENS` sub-chunking (safe at default `eval_batch_size = 64`).
