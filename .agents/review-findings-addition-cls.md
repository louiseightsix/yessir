## 2. Findings (Suspected Bugs, Spec Mismatches, Silent Confounds, or Edge-Case Traps)

**Bottom-line verdict on recorded results and core Python pipeline**: **Zero headline-moving bugs** were found in the `addition` / `cls` Python training, sequence construction, model forward pass, loss computation, free-running rollout, or metric evaluation, and all recorded numbers in `2026-11-17-1bf576e-merry-bream` are faithful and internally consistent.

However, the audit uncovered one **Medium** bug cluster in the web configuration builder (`ConfigBuilder.tsx`) that can silently corrupt `d_model` or `embedding_mode` when generating CLI commands across variants, two **Low** configuration/evaluation edge-case traps in non-default symbol regimes and `fixed_d_model`, and three **Note**-level subtleties.

### [Medium] `ConfigBuilder.tsx` (`web/`) carries untouched variant-specific defaults across variant switches, omits all `addition` validation, and emits broken CLI flags when clearing `eval_ood_bases`

- **Where**:
  - `selectVariant` in [ConfigBuilder.tsx](file:///atelier/code/workshop/yessir/web/src/components/ConfigBuilder.tsx#L238-L251) (contrast `_sync_active_variant` in [tui.py](file:///atelier/code/workshop/yessir/yessir/tui.py#L273-L295)).
  - `validateConfig` in [ConfigBuilder.tsx](file:///atelier/code/workshop/yessir/web/src/components/ConfigBuilder.tsx#L160-L174).
  - `formatCliFlag` in [ConfigBuilder.tsx](file:///atelier/code/workshop/yessir/web/src/components/ConfigBuilder.tsx#L180-L189) and text `<input>` `onChange` in [ConfigBuilder.tsx](file:///atelier/code/workshop/yessir/web/src/components/ConfigBuilder.tsx#L395-L401).
- **Concrete trigger**:
  1. **Silent `d_scratch` / `embedding_mode` carryover across variants**: In `/addition/new/`, `selectVariant` copies `current[f.name]` into `next[f.name]` for every shared field name without checking whether `current[f.name]` was simply the previous variant's untouched default.
     - Opening `/addition/new/` starts on `cls` (`d_scratch = 208`, `embedding_mode = "token_type_pe"`). Clicking `ar` (`default d_scratch = 256`) keeps `d_scratch = 208`, emitting `--d-scratch 208` (`d_model = 464` instead of `512`). Clicking `addressed_step_ar` (`default embedding_mode = "nope"`) keeps `embedding_mode = "token_type_pe"`, emitting `--embedding-mode token_type_pe`.
     - Conversely, loading or resetting on `ar` (`d_scratch = 256`) and clicking `cls` (`default d_scratch = 208`) emits `./yessir.sh run addition cls --d-scratch 256` (`d_model = 256 + 16 + 32 + 256 = 560` instead of `512`), or switching from `addressed_step_ar` (`embedding_mode = "nope"`) to `cls` emits `--embedding-mode nope`.
     - By contrast, the terminal TUI (`_sync_active_variant` in [tui.py](file:///atelier/code/workshop/yessir/yessir/tui.py#L285-L294)) checks `self.values[key] == old_defaults[key]` and swaps untouched defaults cleanly.
  2. **Missing `addition` validation**: `validateConfig` checks `if (expName === "sir_yes_sir")` and otherwise returns `{ valid: true, checks: [] }` unconditionally. Invalid `addition` `cls` combinations (e.g. setting `embedding_mode = "nope"` and `d_position = 0`, `all_steps = true` with `p_terminal = 0.0`, `n_heads = 12` not dividing `d_model = 512`, `eval_extrap_max_length <= max_length`, or `seed == eval_seed`) display green `"Valid"` in the browser and only fail with `ValueError` at CLI launch.
  3. **Malformed CLI flag when clearing `eval_ood_bases` or typing spaces in CSV bases**: Unlike `handleNumericInput` ([ConfigBuilder.tsx](file:///atelier/code/workshop/yessir/web/src/components/ConfigBuilder.tsx#L277-L279)), the text `<input>` handler stores `""` rather than `null` when an optional `str` field (`eval_ood_bases`) is cleared. `formatCliFlag` checks `value === null` (emitting `--eval-ood-bases none`), so `value === ""` emits `--eval-ood-bases ` with a trailing space and no argument—causing bash to pass the next flag (e.g. `--max-steps`) as `--eval-ood-bases`'s value or fail `argparse`. Similarly, spaces in CSV strings (e.g. `"2, 4, 8, 10"`, accepted by `parse_bases_csv`) are emitted unquoted (`--bases 2, 4, 8, 10`).
- **Impact on claims**: Does not affect `merry-bream` or runs launched from Python/TUI/hand-written CLI flags, but could silently confound capacity-matched cross-variant comparisons ([variants-comparison.json](file:///atelier/code/workshop/yessir/studies/addition/variants-comparison.json#L5)) if commands are generated via `/addition/new/` after clicking between variants without clicking `"Reset to defaults"`.

### [Low] Unseen byte tokens on `permuted` (when `symbol_pool` excludes `HEX[:B]`) and on `ood_base*` (when `p_prior == 1.0`)

- **Where**:
  - `AdditionConfig.__post_init__` in [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L180-L214) and `AdditionConfig.eval_splits` in [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L358-L405).
  - `sample_problem` in [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L426-L437).
- **Concrete trigger**:
  1. **`symbol_set="all"` with `symbol_pool_size <= 57` and `eval_permuted_canonical=True` (default)**: For example, `AdditionClsConfig(symbol_set="all", symbol_pool_size=20)` slices `SymbolSet.ALL[:20]`, which consists of byte IDs `0x00..0x13` and contains **none** of the ASCII numeral bytes `SymbolSet.HEX[:10]` (`0x30..0x39`, decimal `48..57`). `__post_init__` only checks `max_train_base <= len(SymbolSet.HEX)` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L204-L208)), not whether `SymbolSet.HEX[:max_train_base]` is contained in `self.symbol_pool`. With `p_prior = 0.0`, training never sees bytes `0x30..0x39` (and in `cls`, rows `48..57` of `ParallelClassificationHead.heads[0..1]` receive exclusively negative cross-entropy gradients), while `permuted` ignores `symbols=config.symbol_pool` and evaluates on `SymbolSet.HEX[:B]`.
  2. **`p_prior == 1.0` with default `eval_ood_bases="3,12"`**: When sweeping `p_prior` up to `1.0` (e.g. [prior-override.json](file:///atelier/code/workshop/yessir/studies/addition/prior-override.json#L5)) on `bases="2,4,8,10"`, `AdditionClsConfig(p_prior=1.0)` is accepted and trains `100%` of steps on the 10 bytes `b"0123456789"`. Because `ood_base3` and `ood_base12` hardcode `p_prior=0.0` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L367)), they draw random alphabets from all 240 bytes of `SymbolSet.ALL`—230 of which never received any Layer 0 input updates or positive `cls` head target updates during training.
- **Impact on claims**: None at default `symbol_pool_size=None` and `p_prior < 1.0`. On `p_prior == 1.0`, `permuted` (the split targeted by [prior-override.json](file:///atelier/code/workshop/yessir/studies/addition/prior-override.json#L5)) remains valid because `permuted` restricts to `SymbolSet.HEX[:B]` over `train_bases`, whereas `ood_base3` and `ood_base12` in the same run's `eval.json` will score `0.0` due to untrained byte embeddings rather than failure of base arithmetic.

### [Note] Minor Distribution, Timing, and Type-Guard Subtleties

1. **Operand asymmetry at injected carry-origin column `i`**: In `sample_problem` ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L453-L454)), `a_vals[i] = rng.randint(1, base - 1)` followed by `b_vals[i] = rng.randint(base - a_vals[i], base - 1)` guarantees `v_a + v_b >= B` as specified in [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L79), but weights `(v_a, v_b)` asymmetrically for `B >= 3`: `(1, B - 1)` is drawn with probability `1 / (B - 1)` while `(B - 1, 1)` is drawn with probability `1 / (B - 1)**2` (`E[v_a] = B / 2` vs `E[v_b] = (3 * B - 2) / 4` at column `i`). The `m` carry-propagating columns (`v_a + v_b == B - 1`, [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L455-L457)) are strictly uniform and symmetric.
2. **`train.jsonl` `elapsed_sec` includes mid-training evaluation wall time**: Both `train_logger` and `eval_logger` start `time.monotonic()` before step 1 ([train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/addition/train_and_evaluate.py#L104-L105), [metrics.py](file:///atelier/code/workshop/yessir/yessir/metrics.py#L31-L39)). In `merry-bream` (`max_steps=50`, `eval_every=10`), `train.jsonl` logs `elapsed_sec = 147.033` at step 50 (including ~140s across evaluations at steps 10, 20, 30, and 40, while excluding the final evaluation at step 50 that brings `eval.jsonl` to `176.98s`).
3. **`bool` subclassing `int` in direct helper calls**: Because `isinstance(True, int)` is `True` in Python, `create_alphabet([False, True])` passes `isinstance(symbol, int) and symbol in SYMBOL_RANGE` ([alphabet.py](file:///atelier/code/workshop/yessir/yessir/alphabet.py#L89-L90), later rejected by `Example._is_int` in [example.py](file:///atelier/code/workshop/yessir/yessir/example.py#L19-L21)), and `int(carry)` in `build_cls_example` ([cls/inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/inputs.py#L45)) coerces `carry=True` to `1`. Neither can occur via `AdditionClsConfig` or `AdditionClsDataset`.

3. **`cls` sequence layout, position coupling, and causal masking (`cls/inputs.py`, `batch.py`, `blocks.py`, `heads.py`)**:
   - Verified `build_cls_example` and `build_cls_step_labelled_example` ([cls/inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/inputs.py#L18-L89)) token-by-token against [cls.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/cls.md#L15-L34):
     - Shared prefix `[BOS] s_0..s_{B-1} [SEP] a_0..a_{L_a-1} [SEP] b_0..b_{L_b-1} [SEP]` assigns `(ALPHABET, 0..B-1)`, `(OPERAND_A, 0..L_a-1)`, `(OPERAND_B, 0..L_b-1)`, and `(SPECIAL, 0)` on `[BOS]` / `[SEP]`.
     - Suffix `c_k [SEP] o_0..o_{k-1}` assigns `(CARRY, k)` to `c_k`, `(SPECIAL, 0)` to the fourth `[SEP]`, and `(OUTPUT, 1..k)` (`range(1, k + 1)`) to `o_0..o_{k-1}` (deliberately differing from `0..k-1` in `step_fork` / `step_ar` where an explicit trailing marker sits at `k`).

Thus at every column `k in 0..K`, the readout position, `c_k`, `a_k`, and `b_k` all share `position_id = k` with zero offset, and no target token `(o_k, c_{k+1}, flag_k)` appears anywhere in the step-`k` input.
   - Verified right-padding and causal masking: `collate` ([batch.py](file:///atelier/code/workshop/yessir/yessir/batch.py#L139-L179)) right-pads `input_ids` with `PAD` and `token_type_ids` / `position_ids` with `0`. In `MultiHeadSelfAttention` ([blocks.py](file:///atelier/code/workshop/yessir/yessir/blocks.py#L277-L280)), `F.scaled_dot_product_attention(..., is_causal=True)` ensures positions `0 .. lengths[b] - 1` never attend to trailing `PAD` positions `>= lengths[b]` in any layer, `RMSNorm` and `SwiGLUFeedForward` are strictly position-wise, and `ParallelClassificationHead` ([heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L112-L116)) indexes `hidden_states[batch_indices, lengths - 1]` prior to projection.
