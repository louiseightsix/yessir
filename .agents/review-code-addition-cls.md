# Code Correctness Audit: `addition` / `cls`

- **Experiment / Variant**: `addition` / `cls` (`CLS_VARIANT`)
- **Audited `HEAD` commit**: `bc2244b9fc121bbbfaf96302e51e7e0082083cac`
- **Historical `results/addition/` commits**: None (`results/addition/` does not exist yet; all 13 study definitions in `studies/addition/*.json` are at `"status": "draft"` with `"runs": []`).
- **Overall Verdict**: **Sound for headline `exact_match` and 4-way first-error taxonomy; zero target-leakage, causal-masking, or position-coupling bugs.** The `cls` implementation faithfully matches [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md) and [cls.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/cls.md). However, **production evaluation (`evaluate_cls`) is strictly teacher-forced across oracle steps and never invokes free-running `rollout_cls`**, which leaves `exact_match` and `FirstErrorType` invariant in exact arithmetic while substantially inflating the secondary headline metric `step_accuracy` (written to `eval.json` and `eval.jsonl`) as well as diagnostic `digit_accuracy`, `carry_accuracy`, and `halt_accuracy` after the first error on a problem. Four minor/edge-case defects and config traps are also documented below.

## 1. Findings (Suspected Bugs, Spec Mismatches, and Correctness Risks)

### Finding 1 (Medium): `evaluate_cls` uses teacher forcing rather than outer-loop rollout (`rollout_cls` is dead code in production runs), inflating `step_accuracy` and post-error diagnostics

- **Location**: [evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/evaluation.py#L52-L67), [run.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/run.py#L35-L45), [generation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/generation.py#L14-L68), [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L143-L150).
- **Expectation vs Actual Behaviour**:
  - [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L143-L146) and [cls.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/cls.md#L75-L81) explicitly define `evaluate_cls` as teacher-forced across all `K + 1` oracle columns, so the implementation conforms to its spec.
  - However, [reviewer-code.md](file:///atelier/code/workshop/yessir/.agents/reviewer-code.md#L34) flags a classic multi-step evaluation hazard: in harnessed variants (`cls`, `step_ar`, `addressed_step_ar`, `step_fork`), evaluation should feed step `k + 1` the model's own predicted carry `c_{k+1}` and output `o_k` and stop on the model's own halt decision with no access to the reference trajectory after problem setup.
  - While `rollout_cls` in [generation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/generation.py#L14-L68) implements genuine free-running rollout (starting from `carry = alphabet[0]`, `output = []`, feeding back predicted `c_next` and `o_k`, stopping on `FLAG_FINISHED` or `max(len(a), len(b)) + 1` without touching `reference_add`), **nothing in [run.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/run.py) or [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/addition/train_and_evaluate.py) ever calls `rollout_cls`**; only unit and convergence tests import it.
  - In `evaluate_cls` ([evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/evaluation.py#L52-L66)), every problem is solved up front by `steps = reference_add(prob.alphabet, prob.a, prob.b)`, and every step `k in 0 .. K` is built with the **oracle** incoming carry `step.carry_in` and **oracle** output prefix `sum_digits[:k]`.
  - Minor spec-text inaccuracy: [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L145) states that `"under bfloat16 autocast, differences in padding and batch shape can flip near-tied argmax decisions"`, whereas `yessir` never uses `bfloat16` autocast (`train_step`, `evaluate_cls`, and `rollout_cls` all run in `float32`, where `eval_batch_size=64` vs `batch_size=1` can still flip near-exact logit ties via BLAS/SIMD reduction order).
- **Concrete Inputs That Trigger It** (verified empirically via Python probes):
  1. *Premature-halt masking*: On `AdditionProblem(tuple(b"0123456789"), tuple(b"1111"), tuple(b"2222"))` (`4` columns), a model that predicts the right `('3', '0')` sum/carry on every column while always predicting `FLAG_FINISHED` halts immediately at `k = 0` in `rollout_cls` (emitting `1` step `[(51, 48, 246)]` instead of `4`), yet `evaluate_cls` ignores the `k = 0` halt and reports `step_accuracy = 1.0`, `digit_accuracy = 1.0` (`exact_match = 0.0`, `halt_accuracy = 0.0`).
  2. *Carry-ripple reset*: On `AdditionProblem(tuple(b"0123456789"), tuple(b"5999"), tuple(b"5000"))` (`9995 + 0005 = 10000`, `5` steps `k = 0 .. 4`), a model that implements exact column addition except failing to carry at `k = 0` (`pred_c[0] = '0'`) produces `[('0', '0', FLAG_CONTINUE), ('9', '0', FLAG_CONTINUE), ('9', '0', FLAG_CONTINUE), ('9', '0', FLAG_FINISHED)]` (`9990`: `0/5 = 0.0` steps right, `1/5 = 0.20` digits right, premature halt at `k = 3`) in `rollout_cls`. Because `evaluate_cls` overwrites `c_k` with the oracle's `'1'` on `k = 1 .. 4`, it reports `step_accuracy = 0.80`, `digit_accuracy = 1.00`, `carry_accuracy = 0.80`, and `halt_accuracy = 1.00`.
- **Impact on Headline and Diagnostic Numbers**:
  - **Headline `exact_match` and all four `FirstErrorType` rates (`out_of_alphabet`, `prior_intrusion`, `procedural_error`, `syntax_malformation`) are unaffected in exact arithmetic**: by induction, if a problem has no error on columns `0 .. k_0 - 1`, then `pred_o[j] == o_j`, `pred_c[j] == c_{j+1}`, and `pred_flag[j] == FLAG_CONTINUE` (`j < k_0 <= K`), so `rollout_cls` reaches column `k_0` (`k_0 <= K <= max(L_a, L_b) < max_columns`) and feeds the exact same `(carry, output)` sequence into step `k_0` as `evaluate_cls`. At `k == K`, `exact_match` requires `pred_flag[K] == FLAG_FINISHED` and `(pred_o[K], pred_c[K]) == (o_K, s_0)`, matching exact tuple equality on `rollout_cls`.
  - **Secondary headline `step_accuracy` (written to `eval.json` and `eval.jsonl` for every split) and diagnostic `digit_accuracy`, `carry_accuracy`, and `halt_accuracy` CAN move substantially**: teacher forcing prevents carry errors, out-of-alphabet/delimiter emissions into `output` (especially under `NOPE` / `TOKEN_TYPE_NOPE`), and premature `FLAG_FINISHED` predictions from cascading into later columns. Readers interpreting `extrap_len_step_accuracy` ([embedding-modes-length.json](file:///atelier/code/workshop/yessir/studies/addition/embedding-modes-length.json)), `carry_accuracy` ([carry-chain-injection.json](file:///atelier/code/workshop/yessir/studies/addition/carry-chain-injection.json)), or `halt_accuracy` ([step-sampling.json](file:///atelier/code/workshop/yessir/studies/addition/step-sampling.json)) must treat them as *single-step teacher-forced transition accuracies*, not free-running rollout step accuracies.

### Finding 2 (Low): Within-`cls` silent config no-ops (`p_terminal` under `all_steps=True`; `d_position` under non-PE modes with `fixed_d_model=False`; `symbol_set` / `symbol_pool_size` under `p_prior=1.0` with no OOD bases)

- **Location**: [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L324-L341), [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L439-L456), [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L426-L430), [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L537-L548).
- **Expectation vs Actual Behaviour**:
  - Flags belonging exclusively to other variants (`step_order`, `use_query_tokens`, `include_alphabet`) are omitted from `AdditionClsConfig` and cleanly rejected (`TypeError` in `AdditionClsConfig.from_dict`, `SystemExit` in `argparse`).
  - Within `AdditionClsConfig`, however, three parameter combinations silently ignore a configured field without validation error or normalisation:
    1. **`p_terminal` when `all_steps=True`**: `iter_problem_steps` in [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L537-L539) yields `k = 0 .. K` sequentially and never consults `p_terminal`, while `AdditionStepConfig` retains `p_terminal=0.2` (or any user-supplied value in `0.0..1.0`).
    2. **`d_position` when `embedding_mode in {TOKEN_TYPE_NOPE, NOPE}` and `fixed_d_model=False`**: `effective_d_position` in [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L324-L329) returns `0` and `effective_d_scratch` in [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L331-L340) returns `self.d_scratch` directly, ignoring `self.d_position` (note: when `fixed_d_model=True`, `self.d_position` *is* folded into `effective_d_scratch` so `d_model` stays constant).
    3. **`symbol_set` and `symbol_pool_size` when `p_prior=1.0` and `eval_ood_bases=None`**: `sample_problem` in [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L426-L427) (`rng.random() < 1.0` is always `True` since `random()` lies in `[0.0, 1.0)`) always constructs `SymbolSet.HEX[:base]`, never reading `symbol_pool` in training or on `id` / `extrap_len` / `permuted` splits.
- **Concrete Trigger** (verified via Python probe):

- **Impact on Headline Numbers**: None on an individual run's accuracy, but creates redundant identical runs if a sweep crosses `all_steps=True` with multiple `p_terminal` values (relevant to [step-sampling.json](file:///atelier/code/workshop/yessir/studies/addition/step-sampling.json)).

### Finding 3 (Low): `_split_seed` collides across consecutive OOD bases `(b, b + 1)` when `seed == eval_seed + 1000 + b`

- **Location**: [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L353-L387).
- **Expectation vs Actual Behaviour**:
  - `_split_seed` in [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L353-L356) computes `candidate = self.eval_seed + offset` and returns `candidate + 1 if candidate == self.seed else candidate`.
  - Because OOD base splits use `offset = 1000 + b` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L385)), when both `b` and `b + 1` appear in `eval_ood_bases` and `seed == eval_seed + 1000 + b`, incrementing `ood_base{b}`'s candidate by `+1` collides with `ood_base{b+1}`'s unshifted seed `eval_seed + 1000 + b + 1`.
- **Concrete Trigger** (verified via Python probe):
  - `AdditionClsConfig(bases="2,8", eval_ood_bases="3,4", eval_seed=999, seed=2002).eval_splits()` assigns `seed = 2003` to **both** `ood_base3` and `ood_base4`. Because `bases` has length `1` on each OOD split (`rng.choice((b,))` consumes zero random bits in Python's `random.Random`), every problem `i` in `ood_base3` draws the exact first `3` symbols of problem `i` in `ood_base4`'s `4`-symbol alphabet.
- **Impact on Headline Numbers**: Zero on default `eval_ood_bases="3,12"` (non-adjacent bases) and default `seed=42, eval_seed=999`, and never collides with the training `seed`.

- **Location**: [metrics.py](file:///atelier/code/workshop/yessir/yessir/metrics.py#L24-L42), [train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/addition/train_and_evaluate.py#L94-L104).
- **Expectation vs Actual Behaviour**:

### Finding 5 (Informational): Experimental interpretation & tooling caveats (`eval_permuted_canonical` default, `3x` `cls` training loss scale, `web/` artefact visibility)

1. **`eval_permuted_canonical=False` default during `p_prior` sweeps**: In [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L158), `eval_permuted_canonical` defaults to `False`, while the `id` and `extrap_len` splits inherit `p_prior=self.p_prior` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L368)). If a run for [prior-override.json](file:///atelier/code/workshop/yessir/studies/addition/prior-override.json) sets `--p-prior 1.0` without explicitly passing `--eval-permuted-canonical`, `permuted` is omitted and `id` evaluates *only* ascending canonical alphabets (`HEX[:B]`), where a model that memorised fixed ASCII digit values without reading the prompt alphabet at all can score `100%` `exact_match`.
2. **`3x` scalar training loss scale relative to `SubspaceLMHead` variants**: `parallel_classification_cross_entropy` in [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L136-L148) sums the per-head mean cross-entropies across `heads[0..2]` (`loss ~ 3 * ln(256) ~ 16.64` at initialisation), whereas `next_token_cross_entropy` in [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L179-L183) in `step_ar`, `step_fork`, `ar`, and `addressed_*` averages across all supervised tokens (`loss ~ ln(256) ~ 5.55`). Because `build_optimizer` in [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L81-L95) uses `AdamW` with `weight_decay=0.0`, multiplying the objective by `3` leaves parameter updates invariant up to `eps=1e-8`, so training is unaffected, but `train.jsonl` `loss` curves in `cls` are scaled by `3x` relative to other variants.
3. **Browser UI visibility**: As noted in [addition-eval-splits-in-web.md](file:///atelier/code/workshop/yessir/.agents/addition-eval-splits-in-web.md), [data.ts](file:///atelier/code/workshop/yessir/web/src/lib/data.ts#L168-L176) reads only `config.json`, `eval.json`, `train.jsonl`, and `README.md`; neither `eval_splits.json` nor the checkpoint trajectory in `eval.jsonl` is rendered in `web/` yet.

## 2. What Was Read and Verified Correct

### A. Data Generation (`inputs.py` & `reference.py`)

- **Ground-truth column addition oracle ([reference.py](file:///atelier/code/workshop/yessir/experiments/addition/reference.py#L69-L186))**:
  - Verified `_validate_inputs`, `_compute_step`, `reference_step`, and `reference_add` line by line and against hand-computed examples:
    - *Spec Example 1* (`B = 10`, `a = b"789"` (`987`), `b = b"52"` (`25`)): `k = 0` (`7 + 5 + 0 = 12` -> `o_0 = '2', c_1 = '1', CONTINUE`), `k = 1` (`8 + 2 + 1 = 11` -> `o_1 = '1', c_2 = '1', CONTINUE`), `k = 2` (`9 + 0 + 1 = 10` -> `o_2 = '0', c_3 = '1', CONTINUE`), `k = 3` (`0 + 0 + 1 = 1` -> `o_3 = '1', c_4 = '0', FINISHED`), yielding `'2101'` (`1012`).
    - *Spec Example 2* (`alphabet = b"q#7"`, `B = 3` with `q = 0, # = 1, 7 = 2`, `a = b"7#"` (`5`), `b = b"#"` (`1`)): `k = 0` (`2 + 1 + 0 = 3` -> `o_0 = 'q', c_1 = '#', CONTINUE`), `k = 1` (`1 + 0 + 1 = 2` -> `o_1 = '7', c_2 = 'q', FINISHED`), yielding `'q7'` (`6`).
    - *Edge cases*: single-column `0 + 0` (`L_a = L_b = 1`, `K = 0`, halts on `k = 0`); single-column carry overflow `1 + 1` in `B = 2` (`K = 1`, runs overflow column `k = 1` with `v_a = v_b = 0, v_c = 1`, emitting `o_1 = s_1, c_2 = s_0, FINISHED`, guaranteed to halt since `B >= 2` implies `total = 1 < B`); MSD zeros (`a = b"500", b = b"2"` steps through all `max(L_a, L_b) = 3` columns before halting); smallest base `B = 2` and largest base `B = 240` (`len(SymbolSet.ALL)`).
    - Unreachable states (`k == 0` with `carry != s_0`, `k == max(L_a, L_b)` with `carry != s_1`, `carry not in {s_0, s_1}`, empty operands, duplicate or special-token bytes in `alphabet`) are all explicitly rejected.
- **Problem & step sampling distributions ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L403-L549), [alphabet.py](file:///atelier/code/workshop/yessir/yessir/alphabet.py#L22-L70))**:
  - Base `B` is drawn uniformly from `bases`; operand lengths `L_a, L_b` are drawn independently and uniformly from `min_length .. max_length`; digits are drawn uniformly from `0 .. B - 1`.
  - `p_prior`: with probability `p_prior`, uses ascending `SymbolSet.HEX[:B]` (which equals `SymbolSet.DECIMAL[:B]` for `B <= 10`); otherwise samples `B` distinct bytes without replacement in uniform random order from `symbol_pool` (`0x00..0xEF`).
  - `permuted_canonical`: rejection-samples `create_alphabet(SymbolSet.HEX[:B], rng=rng)` until `alphabet != canonical`, guaranteeing no accidental identity permutation (so `B = 2` is deterministically `b"10"`).
  - `p_chain`: when `min(L_a, L_b) >= 2`, with probability `p_chain` chooses `m in 1 .. min(L_a, L_b) - 1` and `i in 0 .. min(L_a, L_b) - 1 - m`, setting `a_vals[i] in 1 .. B - 1` and `b_vals[i] in B - a_vals[i] .. B - 1` (`v_a + v_b >= B`, generating a carry regardless of `c_i`) and `m` propagating columns `v_a + v_b == B - 1`. Index bounds are airtight (`i + m <= min(L_a, L_b) - 1`).
  - `p_terminal` & stream decoupling: `iter_problem_steps` uses an independent `random.Random(f"{seed}:step")` instance for column selection (`k = K` with probability `p_terminal`, else `randint(0, K)`, giving `P(k == K) = p_terminal + (1 - p_terminal) / (K + 1)` as specified in [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L80)), keeping the underlying `AdditionProblem` stream identical across `p_terminal` and `all_steps` ablations.
- **Train / eval split disjointness & RNG separation ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L289-L416))**:
  - `eval_seed == seed` is rejected at config construction.
  - `ood_base{b}` strips any base present in `bases` (`b not in train_bases`), guaranteeing 100% base disjointness from training.
  - `extrap_len` samples both `L_a` and `L_b` from `(max_length + 1) .. eval_extrap_max_length` (with `eval_extrap_max_length > max_length` enforced), guaranteeing 100% operand-length disjointness from training. (Note: mixed short+long pairs such as `L_a = 3, L_b = 30` are intentionally excluded so both operands exceed `max_length`.)
  - `permuted` is 100% alphabet-disjoint from `p_prior = 1.0` training; under `p_prior = 0.0` over the 240-byte pool, random draws hit a permuted canonical alphabet only at rate `(B! - 1) / P(240, B)` (`1 / 57360` in `B = 2`, `< 1e-8` for `B >= 4`).
  - `id` uses an independent Mersenne Twister seed (`eval_seed != seed`); over the 240-byte symbol pool even the smallest cell `(B = 2, L_a = 1, L_b = 1)` has `57360 * 4 = 229440` distinct instances (`< 0.01%` overall problem overlap across `6.4M` training draws, though under `p_prior = 1.0` where alphabets are fixed, small-length binary/quaternary problems naturally recur).

### B. Tokenisation, Sequence Coordinates, Masking, and Train-vs-Eval Parity

- **Vocabulary & special-token isolation ([vocab.py](file:///atelier/code/workshop/yessir/yessir/vocab.py#L38-L48), [special_tokens.py](file:///atelier/code/workshop/yessir/yessir/special_tokens.py#L6-L20), [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L20-L43))**:
  - Symbol pool `0x00..0xEF` (`240` bytes), shared special tokens `0xF0..0xF7` (`[SEP]=0xF0`, `[PAD]=0xF1`, `[BOS]=0xF2`, `[EOS]=0xF3`, `[FLAG_CONTINUE]=0xF5`, `[FLAG_FINISHED]=0xF6`), and `AdditionToken`s `0xF8..0xFB` partition `0..255` disjointly. `create_alphabet` rejects any byte outside `0x00..0xEF`, so `[SEP]` and `[PAD]` can never collide with problem symbols.
- **Exact `cls` sequence layout & zero-offset position coupling ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/inputs.py#L18-L55))**:
  - Verified against [cls.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/cls.md#L12-L34):
    - Prefix: `[BOS]` `(SPECIAL=0, pos=0)`, `alphabet` `(ALPHABET=1, pos=0..B-1)`, `[SEP]` `(0, 0)`, `a` `(OPERAND_A=2, pos=0..L_a-1)`, `[SEP]` `(0, 0)`, `b` `(OPERAND_B=3, pos=0..L_b-1)`, `[SEP]` `(0, 0)`.
    - Step state at column `k = len(output)`: `c_k` `(CARRY=4, pos=k)`, fourth `[SEP]` `(SPECIAL=0, pos=0)`, `o_0 .. o_{k-1}` `(OUTPUT=5, pos=1..k)`.
    - At `k == 0`, the final unpadded token (`lengths - 1`) is the fourth `[SEP]` at `pos = 0`; at `k >= 1`, the final unpadded token is `o_{k-1}` at `pos = k`. Thus at every column `k in 0 .. K`, the predicting position, incoming carry `c_k`, and operand digits `a_k` (when `k < L_a`) and `b_k` (when `k < L_b`) all share `position_id == k`.
- **Zero target leakage**:
  - `build_cls_step_labelled_example` in [inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/inputs.py#L58-L89) constructs step `k`'s input from `oracle_steps[k].carry_in` (`c_k`) and `oracle_steps[:k]` (`o_0 .. o_{k-1}`), while supervising `labels = (o_k, c_{k+1}, int(flag_k))`. None of step `k`'s three targets appears in the step suffix.
- **Causal masking, right-padding invariance, and `EmbeddingMode` parity across train, `evaluate_cls`, and `rollout_cls`**:
  - All three paths call the exact same `build_cls_example(..., embedding_mode=...)` -> `make_example` -> `collate` pipeline.
  - `make_example` ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L171-L203)) validates `len(input_ids) == len(token_type_ids) == len(position_ids)` unconditionally before dropping `position_ids` (`TOKEN_TYPE_NOPE`) or both (`NOPE`), while keeping `input_ids` identical across all three modes.
  - `SubspaceEmbedding.forward` in [embedding.py](file:///atelier/code/workshop/yessir/yessir/embedding.py#L119-L127) enforces strict bi-directional checks between `use_token_type` / `d_position` and whether `token_type_ids` / `position_ids` are `None`, making train/eval `EmbeddingMode` mismatches impossible without an immediate `ValueError`.
  - `collate` in [batch.py](file:///atelier/code/workshop/yessir/yessir/batch.py#L59-L98) right-pads `input_ids` with `SpecialToken.PAD` and present `token_type_ids` / `position_ids` with `0`. Because `MultiHeadSelfAttention` in [blocks.py](file:///atelier/code/workshop/yessir/yessir/blocks.py#L102-L115) applies `F.scaled_dot_product_attention(..., is_causal=True)` on equal-length `(B, H, T, d_head)` Q/K/V tensors and `RMSNorm` + `SwiGLUFeedForward` are strictly per-position, tokens at `0 .. lengths[b] - 1` never attend to padded positions `>= lengths[b]`. `ParallelClassificationHead` in [heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L102-L112) gathers `hidden_states[batch_indices, lengths - 1]` prior to its `RMSNorm` and linear projections. Empirically verified `torch.allclose(..., atol=1e-5)` between solo unpadded and right-padded batches across all three `EmbeddingMode`s.

### C. Model Architecture, Classification Heads, Loss, and Config Trace

- **3-head `ParallelClassificationHead` & vocabulary mapping ([heads.py](file:///atelier/code/workshop/yessir/yessir/heads.py#L55-L112), [run.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/run.py#L40-L41))**:
  - `run_addition_cls` instantiates `Transformer` with `head_type=HeadType.PARALLEL_CLASSIFICATION` and `num_classes=(256, 256, 256)` — a learned-gain `RMSNorm(d_model)` followed by 3 independent bias-free `nn.Linear(d_model, 256)` heads (`heads[0]` for `o_k`, `heads[1]` for `c_{k+1}`, `heads[2]` for `flag_k`).
  - Class indices `0 .. 255` map 1-to-1 to byte `Token` IDs (`VOCAB_SIZE = 256`) with no logit masking on any head. Out-of-vocabulary (`< 0` or `>= 256`) predictions are impossible, whereas out-of-alphabet (`0..255 \ alphabet`, including special tokens `0xF0..0xFF`) predictions on `heads[0..1]` and non-flag bytes (`0..255 \ {0xF5, 0xF6}`) on `heads[2]` are possible and handled cleanly without crashes in both `evaluate_cls` and `rollout_cls`. (Using `256` classes on `heads[1]` rather than `2` is essential because `c_{k+1} in {s_0, s_1}` is an in-context byte from `alphabet`, not a fixed binary index.)
- **Loss computation ([training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L98-L148), [training.py](file:///atelier/code/workshop/yessir/yessir/training.py#L253-L264))**:
  - In `train_step`, 1D 3-tuples `(o_k, c_{k+1}, flag_k)` dispatch to single-step `ParallelClassificationHead` (`lengths = batch.lengths`), computing `sum_{h=0..2} F.cross_entropy(logits[h], labels[:, h], ignore_index=-100)`. Prefix positions `0 .. lengths[b] - 2` and padding positions `>= lengths[b]` are never projected and contribute zero loss and zero gradient ([test_heads.py](file:///atelier/code/workshop/yessir/yessir/tests/test_heads.py#L56-L74)).
- **Residual width & `SubspaceEmbedding` ([embedding.py](file:///atelier/code/workshop/yessir/yessir/embedding.py#L52-L156), [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L319-L351))**:
  - Active input slices (`256`-d symbol one-hot, `16`-d token-type one-hot, `d_position`-d sinusoidal with `_SINUSOIDAL_BASE = 256.0` scaled by `1 / sqrt(d_position / 2)`) each have exact L2 norm `1.0`. Sinusoidal encodings are computed analytically in `float32` on the fly with no maximum-length lookup table, so `extrap_len` (`L = 21..40`) never hits an out-of-bounds table index.

### D. Evaluation, Rollout, and Metrics (`evaluation.py`, `generation.py`, `yessir/metrics.py`)

- **Metric definitions & denominators ([evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/evaluation.py#L70-L222))**:
  - `exact_match`: fraction of problems where `classify_first_error` returns `None`, which requires `pred_o[k] == o_k`, `pred_c[k] == c_{k+1}`, and `pred_flag[k] == int(step.flag)` across every step `k in 0 .. K`.
  - `step_accuracy`: fraction of all `sum(K + 1)` steps where both `pred_o[k] == o_k` and `pred_c[k] == c_{k+1}`.
  - `digit_accuracy`: fraction of all `sum(K + 1)` steps where `pred_o[k] == o_k`.
  - `carry_accuracy`: fraction of ground-truth carry-active steps (`step.carry_in != s_0 or step.carry_out != s_0`) where both `(pred_o[k], pred_c[k]) == (o_k, c_{k+1})`, or `None` when `carry_active_steps == 0` (serialised cleanly to JSON `null`). Note that as specified in [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L148), false-positive carries emitted on ground-truth carry-inactive columns penalise `step_accuracy` and `exact_match` rather than `carry_accuracy`.
  - `halt_accuracy`: per-problem fraction where `pred_flag[k] == FLAG_CONTINUE` for all `k < K` and `pred_flag[K] == FLAG_FINISHED` (preventing class-imbalance inflation).
  - `FirstErrorType` partition of unity: on the earliest failing column `k`, checks `(sum_digit, carry_out)` in head order (`SUM_FIRST`) before `halt_ok`. Value mismatches outside `alphabet` map to `OUT_OF_ALPHABET`; in-alphabet mismatches on canonical glyph sets (`set(alphabet) == set(SymbolSet.HEX[:B])`) matching `SymbolSet.HEX[val]` map to `PRIOR_INTRUSION` (impossible to false-trigger on ascending canonical alphabets because `HEX[val] == expected_token != pred_token`); all other in-alphabet value mismatches map to `PROCEDURAL_ERROR`; and halting failures when `(o_k, c_{k+1})` are valid (including non-flag bytes on `heads[2]`) map to `SYNTAX_MALFORMATION`. All four rates divide by `num_problems`, so `exact_match + out_of_alphabet + prior_intrusion + procedural_error + syntax_malformation == 1.0`.
- **Eval mode, gradient disabling, and batch isolation**:
  - Both `evaluate_cls` and `rollout_cls` are decorated with `@torch.no_grad()`, call `model.eval()` before forward passes, carry zero hidden/KV state across batches, and leave the persistent training stream and `AdamW` state untouched across `eval_every` checkpoints (`train_step` restores `model.train()` on the next step).
- **Outer-loop mechanics in `rollout_cls` ([generation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/cls/generation.py#L28-L68))**:
  - Verified that `rollout_cls` itself has zero reference leakage: it validates `(alphabet, a, b)`, bounds execution by `max_columns = max(len(a_tokens), len(b_tokens)) + 1` (computed solely from operand lengths without calling `reference_add`), starts with `carry = alphabet_tokens[0]` and `output = []`, decodes greedy `argmax` from all 3 heads at `lengths - 1` (`[0]`), breaks immediately iff `flag_k == SpecialToken.FLAG_FINISHED`, and feeds `carry = c_next` and `output.append(o_k)` into step `k + 1`.
