### [Low] 2.2 `d_scratch` capacity-sweep trap on `addressed_step_ar` when `fixed_d_model=True` (default)

- **Where**:
  - `AdditionStepConfig` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L438-L445), [config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L486-L495)) and `AdditionAddressedStepArConfig` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L556-L571)).
  - Capacity-sweep studies: [minimum-model-size.json](file:///atelier/code/workshop/yessir/studies/addition/minimum-model-size.json#L1-L8) and [harness-vs-capacity.json](file:///atelier/code/workshop/yessir/studies/addition/harness-vs-capacity.json#L1-L8).
- **Concrete trigger**:
  `AdditionAddressedStepArConfig` inherits `d_scratch: int = 208`, `d_position: int = 32`, and `fixed_d_model: bool = True` from `AdditionStepConfig`, while overriding `embedding_mode` to `EmbeddingMode.NOPE`. Because `effective_d_scratch` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L487-L494)) adds `MAX_TOKEN_TYPES + d_position = 16 + 32 = 48` whenever `fixed_d_model=True` and `embedding_mode=NOPE`:
  1. `AdditionAddressedStepArConfig(d_scratch=0)` (with default `fixed_d_model=True`) builds a model with **`effective_d_scratch = 48` and `d_model = 304`**, whereas `AdditionAddressedArConfig(d_scratch=0)` (which has no `fixed_d_model` field) builds **`effective_d_scratch = 0` and `d_model = 256`**. Even though `addressed_step_ar` did not drop `token_type_ids` or `position_ids` relative to its own `nope` default, `d_scratch=0` still receives `+48` scratchpad dimensions unless `--no-fixed-d-model` is passed.
  2. Conversely, passing `--no-fixed-d-model` alone on `addressed_step_ar` without also setting `--d-scratch 256` silently shrinks the default `nope` model from `d_model = 512` (`effective_d_scratch = 256`) to `d_model = 464` (`effective_d_scratch = 208`).
  3. In recorded `config.json` artefacts, a default `addressed_step_ar` run serialises `"d_scratch": 208, "d_position": 32, "fixed_d_model": true, "embedding_mode": "nope"`, whereas the instantiated `Transformer` actually has `d_scratch = 256` and `d_position = 0` (logged only in `derived_summary()` / stdout `d_model=512`).
- **Headline / study impact**:
  Default runs (`d_model = 512`) are matched across all six variants as specified ([task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L138)), and [harness-vs-capacity.json](file:///atelier/code/workshop/yessir/studies/addition/harness-vs-capacity.json#L5) explicitly notes passing `fixed_d_model=False` when sweeping `d_scratch` down to `0`. However, [minimum-model-size.json](file:///atelier/code/workshop/yessir/studies/addition/minimum-model-size.json#L5) omits that note, so sweeping `--d-scratch` across `addressed_step_ar` vs `addressed_ar` without `--no-fixed-d-model` would silently give `addressed_step_ar` `+48` extra residual/scratchpad dimensions.

### [Note] 2.3 Deterministic overflow-column association (`k = 20` in `B = 10`) and unseen address slots on `extrap_len`

- **Where**:
  - `encode_address` ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L123-L147)), `build_addressed_step_ar_example` ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/inputs.py#L80-L96)), [addressed_ar.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/addressed_ar.md#L19-L25), and [embedding-modes-length.json](file:///atelier/code/workshop/yessir/studies/addition/embedding-modes-length.json#L5).
- **Mechanism**:
  In `addressed_step_ar`, the external harness supplies all `[IDX] addr(j)` headers (`address_accuracy` is `None`), yet content-based address matching (`addr(j) == addr(k)`) on `extrap_len` (`L = 21..40`) still faces two distinct distribution shifts after default `max_length = 20` training:
  1. **Unseen address widths and digit slots** (verified across all bases): in `B = 2`, 6-bit addresses (`32..40`, which also place `s_0` in the `2^4` slot for the first time) and `2^3 = s_1` inside 5-bit addresses (`24..31`); in `B = 4`, `4^2 = s_2` (`32..40`) and `{s_2, s_3}` in `4^1` inside 3-digit addresses (`24..31`); in `B = 8`, `{s_3, s_4, s_5}` in `8^1` (`24..40`); in `B = 10`, `{s_3, s_4}` in `10^1` (`30..40`); in `B = 12`, `{s_2, s_3}` in `12^1` (`24..40`).
  2. **Deterministic overflow shortcut at `k = 20` in `B = 10`**: during training on `L_a, L_b <= 20`, operand addresses `0..19` in base `10` only ever place `s_1` in the `10^1` slot. Symbol `s_2` appears in the `10^1` slot of the step query `[IDX] addr(k)` *exclusively* on the carry-overflow column `k = 20` (`addr(20) = (s_0, s_2)`), where `a_20` and `b_20` are always absent and the ground-truth target is deterministically `(o_20 = s_1, c_21 = s_0, flag_20 = FLAG_FINISHED)` (`100%` conditional probability). On `extrap_len` (`L = 21..40`), columns `k = 20..29` all carry `s_2` in `10^1` as non-overflow columns with active operand digits and `FLAG_CONTINUE`, directly conflicting with any shortcut triggered by `addr(k)[1] == s_2` (especially amplified when `p_terminal = 0.2` oversamples terminal overflow steps).
- **Study impact**:
  Does not invalidate [embedding-modes-length.json](file:///atelier/code/workshop/yessir/studies/addition/embedding-modes-length.json#L5) — `eval_splits.json` already disaggregates `extrap_len_base{b}` — and comparing `addressed_step_ar` against `addressed_ar` cleanly separates address-matching failure from address-generation failure (`address_accuracy`).

### [Note] 2.4 Asymmetric `(a_i, b_i)` sampling on injected carry-originating columns (`p_chain > 0`)

- **Where**:
  - `sample_problem` ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/inputs.py#L450-L458)) and [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L79).
- **Concrete trigger**:
  When carry-chain injection triggers (`p_chain = 0.25` default, `min(L_a, L_b) >= 2`), column `i` draws `a_vals[i] = rng.randint(1, base - 1)` uniformly from `1 .. B - 1` and then draws `b_vals[i] = rng.randint(base - a_vals[i], base - 1)` conditionally. Rather than sampling uniformly over all `B * (B - 1) / 2` pairs with `v_a + v_b >= B`, each pair `(v_a, v_b)` has conditional probability `1 / ((B - 1) * v_a)`, biasing `b_i` larger than `a_i` for `B > 2` (at `B = 10`, `(v_a = 1, v_b = 9)` is `9x` more likely than `(v_a = 9, v_b = 1)`). Propagating columns `j` (`a_vals[j]` uniform in `0 .. B - 1`, `b_vals[j] = B - 1 - a_vals[j]`) are exact uniform over `v_a + v_b == B - 1`.
- **Headline impact**:
  Negligible: `v_a + v_b >= B` holds as specified in [task.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/task.md#L79), non-injected columns (`>= 75%` of problems and non-chain columns) are symmetric i.i.d. uniform, and train/eval splits use the same generator.

### [Note] 2.5 Full-sequence recomputation (`kv_cache=None`) across intra-step and inter-step rollout passes

- **Where**:
  - `_predict_last_token_chunks` and `evaluate_addressed_step_ar` ([evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/evaluation.py#L47-L73), [evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/evaluation.py#L165-L188)), `rollout_addressed_step_ar` ([generation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/generation.py#L50-L76)).
- **Observation**:
  Unlike `evaluate_ar` and `evaluate_addressed_ar` (which prefill left-padded prompts into `KVCache`), `evaluate_addressed_step_ar` runs 3 separate uncached full-sequence right-padded forward passes (`partial = []`, `[t_0]`, `[t_0, t_1]`) at every active column `col_idx` (up to `41 * 3 = 123` full passes of up to `802` tokens on `extrap_len` `B = 2, L = 40`).
- **Impact**:
  **Zero correctness impact** — using right-padded `collate` with `[BOS]` at index `0` makes evaluation forward passes identical to training forward passes and avoids any `KVCache` or left-padding mask bugs — while costing `~3x` intra-column compute during periodic evaluations.

   - Verified token-by-token against [addressed_step_ar.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/addressed_step_ar.md#L33-L52) and [addressed_step_ar.md](file:///atelier/code/workshop/yessir/experiments/addition/spec/variants/addressed_step_ar.md#L83-L88) across all combinations of `step_order` (`sum_first` / `carry_first`), `use_query_tokens` (`False` / `True`), `include_alphabet` (`True` / `False`), and `embedding_mode` (`nope`, `token_type_nope`, `token_type_pe`):

[IDX] addr(k-1) o_{k-1} [SEP] [IDX] addr(k)` ([inputs.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/inputs.py#L79-L96)), with multi-digit `addr(j)` tokens all receiving `(TokenType.ADDRESS, position_id = j)`, `o_k` receiving `(TokenType.OUTPUT, k)`, `c_{k+1}` receiving `(TokenType.CARRY, k + 1)`, and query tokens `([S], [C], [F])` receiving `(TokenType.SPECIAL, k)`.

5. **End-to-end plumbing of all 32 config fields**:
   - Traced every field of `AdditionAddressedStepArConfig` ([config.py](file:///atelier/code/workshop/yessir/experiments/addition/config.py#L556-L571)) from CLI (`add_config_args` / `build_config_from_args` in [experiment.py](file:///atelier/code/workshop/yessir/yessir/experiment.py#L127-L197)) and TUI ([tui.py](file:///atelier/code/workshop/yessir/yessir/tui.py#L64-L111)) through `run_addition_addressed_step_ar` ([run.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/run.py#L22-L60)) and `train_and_evaluate` ([train_and_evaluate.py](file:///atelier/code/workshop/yessir/experiments/addition/train_and_evaluate.py#L49-L239)). 6. **Free-running rollout, halting, token-bounded chunking, and metric definitions**:
   - `evaluate_addressed_step_ar` ([evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/evaluation.py#L163-L210)) and `rollout_addressed_step_ar` ([generation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/generation.py#L48-L85)) decode `(t_0, t_1, flag_k)` autoregressively in 3 passes per column, feed the model's own unpacked `(pred_o, pred_c)` (including arbitrary out-of-alphabet or special tokens `0..255` without crashing) into `col_idx + 1`, and bound outer iterations purely by input operand lengths `max(len(a), len(b)) + 1` with zero reference-trajectory leakage.
   - Halting edge cases verified by script: premature `FLAG_FINISHED` at `k < K`, non-halting `FLAG_CONTINUE` on an overflow problem `len(steps) == max(L_a, L_b) + 1`, and non-flag garbage bytes (e.g. `ord('0')`) on `k < K` all fail `halt_ok`, `halt_accuracy`, and `exact_match`, classifying as `FirstErrorType.SYNTAX_MALFORMATION`.
   - `oracle_step_accuracy` ([evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/evaluation.py#L193-L248)) reuses rollout predictions when `(carries[i], outputs[i])` matches the ground-truth prefix and falls back to single-pass teacher forcing (`offsets = (-5, -3)` or `(-3, -2)`) otherwise; because `oracle_ok` is the conjunction `(pred_t0 == step_t0) and (pred_t1 == step_t1)`, rollout conditioning `t_1` on `pred_t0` vs teacher-forced `step_t0` can only differ when `pred_t0 != step_t0`, where the conjunction is already `False`.
   - Token-bounded sub-chunking (`MAX_EVAL_CHUNK_TOKENS = 65_536`, [evaluation.py](file:///atelier/code/workshop/yessir/experiments/addition/variants/addressed_step_ar/evaluation.py#L28-L45)) keeps default `eval_batch_size = 64` unsplit on worst-case `B = 2, L = 40, use_query_tokens=True` (`802 * 64 = 51,328 <= 65,536`) while safely sub-chunking larger batch sizes down to `sub_size >= 1`.
